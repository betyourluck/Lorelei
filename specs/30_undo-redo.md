# Spec: 操作を元に戻す・やり直す（Undo/Redo）

**ID**: 30
**Date**: 2026-10-30
**Status**: **Active** — rev1（起票 → 査読 1 本（「査読の採否」）→ rev1 → 裁定（「裁定」、推奨どおり）→ P0（「P0 結果」）→ P1 着地（「P1 結果」）。残りは P2（デスクトップ）・P3（配布ビルド）。rev1 で「確定へ戻す」を [spec 32](32_revert-to-confirmed.md) へ分けた）
**Branch**: 切らない（Phase 単位で main へ直接コミット）。Undo/Redo はエディタ（フォーク元の部品）の改善なので、**フォーク元の改善と台帳・デスクトップはコミットを分け**、フォーク元のコミットだけで上流へ PR を出せる形にする（PR を出すかは利用者が決める, CLAUDE.md）

## Goal

利用者の言（2026-10-30）: 「確定ボタンを押される前に戻すボタンが欲しい（やり直し）UndoRedo。現在では確定ボタンはほとんど意味をなしていない。せめて確定するまえに戻せるなどがよい」

エディタの操作を 1 手ずつ元に戻す・やり直せるようにする（Web 版とデスクトップ）。
「確定」を戻れる区切りにする（最後に確定した中身へ戻す）のは [spec 32](32_revert-to-confirmed.md)（rev1 で分けた。Rust の `Document`・`unsaved` の意味・MCP の契約に及ぶため）

## 裁定（2026-10-31、利用者）

利用者の言: 「推奨どおりで進める」 — D1〜D8 を推奨どおりに決めた（D1: 中身の鍵が変わった時に 1 手、途中は保留してまとめる / D2: Ctrl+Z・Ctrl+Y・Ctrl+Shift+Z、Mac は ⌘Z・⌘⇧Z、文字の入力の中は欄に任せる /
D3: 図の id に結び付け、準備ができた時を起点、図が替わったら・載せ替えで捨てる / D4: 載せ替えで履歴を捨てる / D5: 準備の途中・モーダル・確認・ドラッグの間は効かない /
D6: 口は `lib/desktop` を参照しない形でフォーク元に / D7: 案 A（配列の参照を持つ） / D8: 削除の確認の文から「元に戻せません。」を外す）

## P0 結果（2026-10-31、コードを読んで形を決めた）

- **置き場所**: `components/editor-history/`（フォーク元の改善。2 つのエディタで共有）
  - `history.ts`（純粋な部分）: `contentKey(snapshot)`・`EditorHistory`（`reset` / `record` / `undo` / `redo`、上限 100）・`restoreNodes`・`nextNodeId`
  - `use-editor-history.ts`（hook）: エディタの state と setter を受け、記録・キー・戻す・やり直すを持つ。返すのは `{ undo, redo, canUndo, canRedo }`
  - `gate.ts`: `HistoryGateContext`（`{ ready: boolean; epoch: unknown }`。Web 版は既定の `{ ready: true, epoch: 0 }`）。デスクトップは `lib/desktop` が Provider で包んで渡す（P2）
- **中身の鍵**: ノードは `id`・`type`・`parentId`・`position`・`width`・`height`・`data`、線は `id`・`source`・`target`・`sourceHandle`・`targetHandle`・`type`・`data`、それに図の向きとテーマを `JSON.stringify` したもの
  （`data` の関数は JSON に入らないので自然に外れる。`selected`・`dragging`・`resizing`・`measured` は欄を選ぶので入らない）。次のノードの番号は写しには持つが鍵には入れない
- **記録**: state が変わった描画の後に、次のフレームで鍵を比べ、違えば 1 手（同じフレームの中の変更はまとまる — 枠の削除の付け替え → remove → 線の remove）。
  ドラッグ・大きさの変更の途中（`dragging` / `resizing` のノードがある）とダイアログ（`role="dialog"` / `alertdialog`）が開いている間は記録を保留し、次の変更か Undo を押した時にまとめて 1 手にする
  （確認を挟む付け替え・削除は、確認の後の state で 1 手）
- **戻す**: 戻す前に保留の変更を 1 手として記録してから、1 つ前の写しを当てる。ノードは `selected`・`dragging`・`resizing` を落とし、`measured` は今の同じ id の値を当てる。線は `selected` を落とす。
  次のノードの番号は今の値と戻したノードの数字の ID の最大 + 1 の大きい方
- **起点**: `HistoryGate` の `ready` が true になった時と `epoch` が変わった時に、その時の state を起点にして履歴を捨てる。`ready` が false の間は記録も戻しもしない
- **キー**: `document` の keydown。文字の入力の中（`input` の文字の種類・`textarea`・contenteditable）と IME の変換中は何もしない。ダイアログが開いている間・ドラッグの途中も何もしない
- data_contract に `EditorHistory`・`HistoryGate` を書いた

## 決めること

### D1. 1 手の数え方

- **推奨: 入口ごとに記録するのではなく、エディタの状態の「中身の鍵」が変わった時に 1 手とする（差分）**。
  中身の鍵 = ノード（ID・type・parentId・位置・枠の width/height・`data` から関数を除いたもの）・線（ID・端・`data` から関数を除いたもの）・図の向き・テーマ。
  `selected`・`dragging`・`resizing`・`measured` は入れない。比べるのはエディタの state（ER 図は描くたびに新しいオブジェクトになる xyflow のストアではない）
  - これで、クリックだけ・同じ値の確定・付け替えをやめた時・ResizeObserver は手にならず、入口の数え漏れ（枠の大きさ・矢印キー・Backspace・ER 図のセル）も拾える
- **まとめ方**: ドラッグ中・大きさを変えている途中・確認のダイアログの途中は記録を保留し、終わった時の状態で 1 手。
  同じ操作で変更が分かれて届くもの（枠の削除の付け替え → remove → 線の remove）は、次のフレームまでまとめて 1 手
- ラベル・変数名・枠の題・セルは入力を確かめた時（Enter・blur）に state が変わるので、その時に 1 手（1 文字ずつではない）
- **Web 版のパネルからのインポートは 1 手**（戻すと取り込む前の図）。**デスクトップの開く・載せ替えは手にしない**（D3）

### D2. 押し方

- **推奨**: Ctrl+Z で戻す、Ctrl+Y と Ctrl+Shift+Z でやり直す。Mac は ⌘Z と ⌘⇧Z（⌘Y は Safari で履歴を開くので使わない）
- **文字の入力の中（`input` の文字の種類・`textarea`・contenteditable。CodeMirror を含む）にフォーカスがある時は、その欄の取り消しに任せて図の Undo はしない**。
  チェックボックス（ER 図の PK など）・ボタンにフォーカスがある時は図の Undo をする（xyflow の `isInputDOMNode` のように input 全般で止めると、PK を押した直後の Ctrl+Z が効かない）。IME は文字の入力の中だけで起きるので、この規則で足りる
- ボタン: デスクトップはツールバーに ↶ ↷（`useDesktopActions` に `undo` / `redo` を足す。「押せるか」は `register` を毎手走らせないよう、別の小さな状態で渡す）。
  Web 版はフォーク元のパネルに同じボタン。戻せる手が無い時は押せない

### D3. 履歴の持ち方と捨てる時

- **推奨**: エディタごとに画面の中だけで持つ（ファイルには書かない）。上限 100 手。新しい手を打つとやり直せる手は消える
- **デスクトップでは、履歴を今の図の id に結び付け、図が準備できた時（`settled` かつ `readyRef`）の状態を起点にする**。
  捨てる時: 一覧から別の図を開いた時（エディタの作り直し）・`beforeImport` で図の id が変わった時（AI の `open_in_editor`・ツールバーのインポート）・`STALE_BASE` からの開き直し（`use-doc-session.ts:162`）・**AI の載せ替え**（D4）・アプリを閉じた時
  - これが無いと、開いた直後の Ctrl+Z で初期図に戻ってそれが保存される（failures #7・#13 の形）、別の図に前の図の中身が書かれる
- 戻した結果は自動保存で書かれ、`updated_at` が進む。● は時刻で決まるので、確定と同じ中身に戻しても ● は残る（今の規則のまま。中身で決めるかは spec 32）

### D4. AI の書き換え（`update_diagram`）の載せ替え

- **推奨（rev1 で改めた）: 載せ替えで履歴を捨てる**（載せ替えの後の状態を新しい起点にする）。AI の変更を取り消すのは spec 32 の「確定へ戻す」で
- rev0 の「載せ替えを 1 手にする」は、載せ替えが数段に分かれる（取り込み → 次の描画で位置）うえ、**載せ替えから 1 秒以内に戻すと、戻した中身が揃え書きとして `updated_at` を進めずに書かれ、AI が人の戻しを知らずに上書きできる**（査読 5）。
  取り込みと位置を 1 回で当てる口と、揃え書きとの順序を決めてから入れる（spec 32 で「確定へ戻す」の載せ直しと同じ仕組みで扱う）

### D5. 効かない時

- **推奨: 次の間は Undo / Redo（キーとボタン）を効かせない**
  - デスクトップで図が準備できるまで（開く・載せ替えの途中。ここで戻すと届いた図のキーがそろわず、準備ができないまま自動保存が止まる — 査読 3）
  - モーダル（削除の確認・コード生成・インポート・設定）が開いている間、`onBeforeDelete` の確認・付け替えで線を消す確認（`askDelete`）を待っている間
    （確認の後に当てる計画は前の state で作ったものなので、戻した結果と食い違う）
  - ドラッグ・大きさの変更・線をつないでいる最中

### D6. デスクトップとの口（フォーク元の改善のまま）

- 履歴はフォーク元のエディタに入れる（Web 版でも効く）。P1 が着地した時点でデスクトップにも効くので、**D3・D5 の止め方を P1 に含める**（分けると危ない形で着地する）
- 口は `lib/desktop` を参照しない形にする（例: `components/` に「今は記録・戻してよいか」と「起点を置き直す」を受け取る Context。Web 版では何も渡さず常に可。デスクトップは `lib/desktop` から渡す）。
  spec 02 D7（エディタに保存用の口を足さない）と CLAUDE.md の差し込みの数え方が変わるので、台帳に書く

### D7. 作り方

- **推奨（rev1 で決めた）: 案 A — 手ごとに `nodes` / `edges` の配列の参照と、図の向き・テーマ・次のノードの番号を持つ**。変更は不変更新なので、変わっていないノードは同じものを指し、記録はほぼタダ
  - 戻す時は `selected`・`dragging`・`resizing` を落とす（`dragging` が残ると、手を離した時の線の全部の探し直しが走らない, failures #38）
  - `measured` は今の同じ id のノードの値を当てる（全部外すと xyflow が測り直すまでノードと線が消える）。今に無いノードは xyflow の測りに任せる
  - 次のノードの番号は「今の値」と「戻したノードの数字の ID の最大 + 1」の大きい方（インポートで番号が下がるので、戻すと ID が重なる）
- 案 B（生成器の出力と位置で持つ）は採らない: 生成器が書かない状態が戻らない（ER 図の空の列, spec 13）、取り込むとノードの ID が変わって全部作り直される、取り込みは非同期で重い（Web は mermaid.js、デスクトップは IPC）

### D8. 削除の確認の文

- **推奨: 「元に戻せません。」を外す**（「つながっている線も一緒に消えます。」だけにする）。確認そのもの（spec 06）は残す

## 受け入れ条件（rev1）

1. 2 つのエディタで、D1 の操作（枠の大きさ・矢印キーの移動・Backspace・ER 図のセル・PK/UK/FK・カラム追加・行の削除を含む）が 1 手ずつ戻り、やり直せる。戻した後の生成器の出力・位置・枠の親子が、その手の前と同じ
2. 選ぶ・クリックだけ・同じ値の確定・付け替えをやめる操作は手にならない。枠の削除・確認を挟む付け替えは 1 手
3. Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z（Mac は ⌘Z・⌘⇧Z）とボタンで動く。文字の入力の中では図の Undo をせず、チェックボックスの後では図の Undo をする
4. デスクトップ: 開いた直後・載せ替えの直後の Ctrl+Z で、初期図・自動配置・前の図に戻らない。AI が新しい図を開いた後・インポートで新しい図ができた後に、前の図の手が残っていない。準備ができるまでの Ctrl+Z で自動保存が止まらない
5. D5 の間は効かない
6. 戻した結果が自動保存され、開き直しても戻した中身が出る（デスクトップ）
7. 戻した後にノードを足しても ID が重ならない。戻した後のドラッグで線の探し直しが走る
8. テスト（vitest）: 中身の鍵（`measured`・`selected` を無視する）・記録と戻し・上限・やり直しが消える・フォーカスの規則・デスクトップの開く・載せ替え・切り替えとの関係（`fake-backend.ts` と `update-diagram.test.tsx` の形で）。要の分岐を壊して落ちる
9. 実画面（Web 版は裏の Edge、デスクトップは `tauri dev` と配布ビルド）: ドラッグ・大きさの変更・矢印キー・ラベルの編集中にツールバーの ↶ を押した時（blur で確定 → その手を戻す）・IME。**macOS の ⌘Z**（配布ビルドで、ネイティブのメニューに取られないか）
10. 配布ビルドで利用者が確かめる

## Phase

- **P0**: 中身の鍵とまとめ方（削除・ドラッグ・確認）の当たりを付ける。D6 の口の形。data_contract の名詞を凍結（`EditorHistory`・`HistoryGate` など）（**台帳のコミット**）
- **P1**: 2 つのエディタの履歴・キー・Web 版のパネルのボタン・D5 の止め方の口・削除の確認の文（**フォーク元の改善のコミット**）→ Web 版で確かめる
- **P2**: デスクトップ — `lib/desktop` から口に渡す（準備・図の id・載せ替え・モーダル）、ツールバーの ↶ ↷ → `tauri dev` で確かめる（受け入れ条件 4 の台本、failures #4〜#13 の台本を回し直す）
- **P3**: 配布ビルドで利用者が確かめる（macOS の ⌘Z は CI のビルドを入れて確かめるか、未確認として残すかを P3 で決める）

## スコープ外

- 「確定へ戻す」・確定した中身を残す・● を中身で決める・AI の書き換えを 1 手で戻す（[spec 32](32_revert-to-confirmed.md)）
- 履歴をファイルに残す（アプリを閉じても戻せる）・履歴の一覧から選んで戻す
- `history/`（`update_diagram` の 1 世代）を GUI から戻す
