# Spec: フローチャートのノードに形のアイコンを出す

**ID**: 29
**Date**: 2026-10-30
**Status**: **Draft** — rev0（起票。D1〜D5 の裁定待ち）
**Branch**: 切らない（Phase 単位で main へ直接コミット）。ノードはフォーク元の部品なので、**フォーク元の改善と台帳はコミットを分け**、フォーク元のコミットだけで上流へ PR を出せる形にする（PR を出すかは利用者が決める, CLAUDE.md）

## Goal

利用者の言（2026-10-30）: 「ノード形状のアイコンをノードの右上にでもつけて欲しい（現状はどの形かわからない）」

フローチャートのノードが Mermaid のどの形（四角形・菱形・角丸・円・六角形・スタジアム）になるのかを、Mermaid の書き方を知らない人にも一目で分かるようにする。Web 版とデスクトップで同じ。

## 現況（2026-10-30、コードを読んだ）

- **ノードは形にかかわらず同じ四角で描かれる**: `features/flowchart/components/node/editable-node.tsx` の `NodeContent` の外枠の `Box`（`border 2px`・`borderRadius md`・`w xs`）は `data.shapeType` を見ていない
- **形が分かるのは左上の青い札だけ**: `components/editor/variable-name-editor.tsx` が変数名を `formatMermaidShape(shapeType, 変数名)` で括弧に包んで出す（例 `{node2}`・`((node3))`）。Mermaid の記法を知らないと読めない
- **右上の角には操作メニューがある**: `node-menu.tsx` の `MenuButton`（`GripIcon`、`position absolute`・`top 0`・`right 0`、ノードの内側）。形を変えるのはこのメニューの「ノード形状」→ `ShapeSelector`（`shape-selector.tsx`、項目は `SHAPE_OPTIONS` の日本語の名と記号 `[ ]`・`{ }` …）
- **形は 6 つ**: `MermaidShapeType`（`types/types.ts`）= `rectangle` / `diamond` / `rounded` / `circle` / `hexagon` / `stadium`。ほかの形（`cylinder` など）は取り込みで落ちる（`components/ui/mermaid-dropped.ts` の `shape:…`）
- **アイコン**: `lucide-react` 0.475.0（spec 23 で直接の依存に足した）に `square`・`diamond`・`circle`・`hexagon`・`pill`・`rectangle-horizontal` はあるが、
  角丸の四角（Mermaid の `(…)`）と四角形を見分けられる組は無い（`rectangle-horizontal` も角が丸い）
- **ノードの大きさと線の回し方**: 線を回す処理（spec 17〜22 の `edge-route.ts`）はノードを xyflow の測った矩形として扱う。札は `position absolute` なので測った大きさに入らない（左上の変数名の札と同じ）

## 決めること

### D1. アイコンの置き場所

- **案 A（推奨）: 右上の縁の上に札として出す**（左上の変数名の札と対。`top: -12px`・`right: 0` 前後、ノードの外）。
  ノードの内側の幅を食わず、⋮⋮ のメニューと重ならない。札は測った大きさに入らないので、線の回し方は変わらない
- 案 B: ノードの内側、⋮⋮ の左隣 — ラベルが長いと右上の角に寄って重なりうる
- 案 C: ノードそのものを形どおりに描く（菱形・円…）— Mermaid の見た目に一番近いが、接続点の位置・測った大きさ・線を回す処理（spec 17〜22）が全部変わる。**採らない**（スコープ外）

### D2. アイコンを押した時

- **推奨: 形のメニューを開く**（`ShapeSelector` と同じ 6 つの項目。今の ⋮⋮ →「ノード形状」の近道）。`title` と `aria-label` に形の名（「菱形」など）
- 案: 押しても何もしない（見せるだけ）

### D3. 左上の札の括弧

- **推奨: 今のまま残す**（Mermaid を知る人には、生成されるコードと同じ記法で分かる。アイコンと情報が重なっても害は無い）
- 案: 括弧を外して変数名だけにする

### D4. アイコンの絵

- **推奨: 6 つとも自前の SVG で描く**（16px、線は `currentColor`。Mermaid が描く形の輪郭をそのまま縮めたもの: 四角形は角が尖り、角丸は角が丸く、スタジアムは両端が半円）。
  lucide では角丸と四角形が見分けられない（現況）ので、組をそろえるために全部自前にする
- 同じアイコンを `ShapeSelector` の各項目にも出す（今の記号 `[ ]` などは残す）

### D5. 範囲と色

- フローチャートのノードだけ（ER 図のテーブル・枠は形を持たない）。Web 版とデスクトップで同じ（キャンバスはフォーク元の部品なので、デスクトップの差し込みは要らない）
- 色は spec 27 の色の名を使う（札の地と線。ライトと dark でキャンバスの地に対して 3:1 以上）。選んだ時の輪（spec 28）と重ならないこと（輪は外側 2px なので、札は輪の外に出る位置にする）
- 形の名の文字は今は日本語のまま（UI の言語の切り替えは spec 31 で `SHAPE_OPTIONS` の名と一緒に移す）

## 受け入れ条件（rev0）

1. フローチャートの 6 つの形のノードに、形ごとに見分けられるアイコンが出る（ライトと dark）。形を変えるとすぐ変わる
2. アイコンに形の名（`title`・`aria-label`）。D2 で採れば、押すと形のメニューが開き、選ぶと形が変わる
3. ノードの測った大きさ・接続点・線の回し方は前と同じ（札がノードの矩形に入らない）。選んだ時の輪（spec 28）と札が重ならない
4. 選んでいない時の、アイコン以外の見た目は前と同じ（spec 27 の台本でライトの計算されたスタイルを比べる）
5. テスト（vitest）: 6 つの形でアイコンが違う・形を変えると変わる・（D2）押すとメニュー。要の分岐を壊して落ちる
6. 配布ビルドで利用者が確かめる

## Phase

- **P1**: アイコンの部品とノードの札・`ShapeSelector` の項目（**フォーク元の改善のコミット**）→ Web 版で裏の Edge（6 つの形・ライトと dark・コントラスト・台本）
- **P2**: 配布ビルドで利用者が確かめる

## スコープ外

- ノードを形どおりに描く（D1 案 C）
- 6 つより多くの形（`cylinder`・`subroutine` など。取り込みで落ちるのは今のまま）
- 形の名の翻訳（spec 31）
