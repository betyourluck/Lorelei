# Spec: フローチャートのノードに形のアイコンを出す

**ID**: 29
**Date**: 2026-10-30
**Status**: **Draft** — rev1（起票 → 査読 1 本（「査読の採否」）→ rev1。D1〜D7 の裁定待ち）
**Branch**: 切らない（Phase 単位で main へ直接コミット）。ノードはフォーク元の部品なので、**フォーク元の改善と台帳はコミットを分け**、フォーク元のコミットだけで上流へ PR を出せる形にする（PR を出すかは利用者が決める, CLAUDE.md）

## Goal

利用者の言（2026-10-30）: 「ノード形状のアイコンをノードの右上にでもつけて欲しい（現状はどの形かわからない）」

フローチャートのノードが Mermaid のどの形（四角形・菱形・角丸・円・六角形・スタジアム）になるのかを、Mermaid の書き方を知らない人にも一目で分かるようにする。Web 版とデスクトップで同じ。

## 現況（2026-10-30、コードを読んだ。rev1 で査読の確かめを足した）

- **ノードは形にかかわらず同じ四角で描かれる**: `features/flowchart/components/node/editable-node.tsx` の `NodeContent` の外枠の `Box`（:179-196。`border 2px`・`borderRadius md`・`w xs` = 15rem = **240px**）は `data.shapeType` を見ていない。
  外枠に `onDoubleClick`（:192、ラベルの編集を始める）
- **形が分かるのは左上の青い札だけ**: `components/editor/variable-name-editor.tsx` が変数名を `formatMermaidShape(shapeType, 変数名)` で括弧に包んで出す（:33、例 `{node2}`・`((node3))`）。
  札は `position absolute`・`top -12px`・`left 0`・`zIndex 10`・`bg blue.500`・文字 10px（:36-50）。**幅に上限が無く**、長い変数名だとノードの右の方まで伸びる。`nodrag` は付いていない（`stopPropagation` は click だけ）
- **右上の角には操作メニューがある**: `node-menu.tsx` の `MenuButton`（:25-36。`IconButton` の `xs` = 高さ **24px**、`absolute`・`top 0`・`right 0`、ノードの内側の (216..240, 0..24)、`nodrag`）。
  その `MenuList`（:38）は **Portal を使っていない**（failures #28 の後に Portal にしたのは `frame-direction-menu.tsx:47`・`arrow-type-selector.tsx:97` だけ）。
  形を変えるのはこのメニューの「ノード形状」→ `ShapeSelector`（`shape-selector.tsx`、`MenuButton as={MenuItem}` の入れ子のメニュー。親の `MenuList` の外では使えない）
- **形は 6 つ**: `MermaidShapeType`（`types/types.ts:9-15`）= `rectangle` / `diamond` / `rounded` / `circle` / `hexagon` / `stadium`。表に無い形は取り込みで `rectangle` にし、`shape:<名>` を落としたものとして知らせる（`from-mermaid.ts:89-97`、`components/ui/mermaid-dropped.ts:36`）
- **アイコン**: `lucide-react` 0.475.0（`package.json:53`）の `square`・`rectangle-horizontal` はどちらも角が丸い（`rx="2"`）。`hexagon` は上下が尖る縦向き（Mermaid の六角形は左右が尖る）。`pill` は斜めのカプセルで中に線がある。**6 つの形をそのまま表せる組は無い**
- **選んだ輪**（spec 28、`components/layout/selection-ring.ts`）: `outlineOffset 2px`・`outlineWidth 3px` なので、**ノードの外側 2〜5px の帯**に描く。今の左上の札（-12〜+5px 前後）はこの帯を跨いでいて、輪の上に描かれる
- **ノードの大きさと線の回し方**: xyflow はノードを `offsetWidth / offsetHeight` で測るので、`position absolute` の札は大きさに入らない。
  線を回す処理（spec 17〜22、`use-edge-routes.ts:99-107`・`edge-route.ts`）が避けるのはノードの測った矩形だけで、**札は避けない**（左上の札も同じ。`edge-route.ts`・`use-edge-routes.ts` に札・変数名に触れるコードは無い）。
  回した線は縁から 6〜12px まで寄りうる。線のボタン（高さ 28px）の上下は、枠の無い図ではノードより下、枠のある図では一番上の枠の z + 1（`editable-edge.tsx`）
- **接続点**: 上の縁の接続点は真ん中（x = 120）。右上には来ない（左右の接続点は高さの真ん中）
- **枠の中のノード**: 取り込み・出し入れの後は、中のノードの上端と枠の見出しの下端の間が 24px 以上（`frame-edit.ts:166`）。札が上へ 20px 前後出ても見出しには届かない
- **重さ**: 閉じた yamada-ui の `Menu` も項目を DOM に持ち、描き直しが重い（spec 23 では線のラベル 1 本あたり 2〜2.5ms）。ノードは今でも `NodeMenu` と `ShapeSelector` の 2 つの `Menu` を持つ
- **見た目の台本**（spec 27 の `scripts/ui-style-snapshot.mjs:91-98`）は要素を「親の何番目の子か」の道筋で呼び、`ui-style-compare.mjs` は片方にだけある要素があると失敗にする。コントラストの測りは `svg` の中を飛ばす
- フォーク元の VRT（`__image_snapshots__/components-node-nodecontent--default.png`、stories の `tags: ["vrt"]`）はノードの見た目を持つ。Lorelei では回していない
- `lib/desktop/`・`app/` はノードの部品も `SHAPE_OPTIONS` も参照していない（デスクトップの差し込みは要らない）

## 決めること

### D1. アイコンの置き場所

- **案 A（推奨）: 右上の縁の上に札として出す。札の下端をノードの上の縁（y = 0）にそろえ、右端はノードの右端にそろえる**（`bottom: 100%`・`right: 0`、ノードの外）。
  ⋮⋮（y = 0〜24）とは重ならない。ノードの内側の幅を食わない。札は測った大きさに入らないので、線の回し方は変わらない。
  左上の変数名の札（`top -12px`）とは高さが少し違う（左の札は今のまま）
- 案 B: ノードの内側、⋮⋮ の左隣 — ラベルが長いと右上の角に寄って重なりうる
- 案 C: ノードそのものを形どおりに描く（菱形・円…）— Mermaid の見た目に一番近いが、接続点の位置・測った大きさ・線を回す処理（spec 17〜22）が全部変わる。**採らない**（スコープ外）

### D2. アイコンを押した時

- **推奨: 形のメニューを開く**（6 つの形。今の ⋮⋮ →「ノード形状」の近道）。札のボタンの `title` と `aria-label` に形の名（「形: 菱形」など）
  - メニューは **Portal で出す**（枠の中のノードでも、後ろのノードや線のボタンに隠れない, failures #28）
  - 6 つの項目は部品に切り出し（例 `ShapeMenuItems`）、⋮⋮ の「ノード形状」と札のメニューの両方から使う（`ShapeSelector` の入れ子のメニューは親の外で使えないため）
  - 札に `nodrag` を付け（押してもノードのドラッグを始めない）、ダブルクリックは外枠へ伝えない（ラベルの編集を始めない）
- 案: 押しても何もしない（見せるだけ）

### D3. 左上の札

- **推奨: 括弧は今のまま残す**（Mermaid を知る人には、生成されるコードと同じ記法で分かる）
- **左上の札に幅の上限と省略を付ける**（右上の札の手前まで。全文は `title`）。長い変数名で右上の札にぶつかる・上の接続点を隠すのを防ぐ（査読 3。今もある穴）
- 案: 括弧を外して変数名だけにする

### D4. アイコンの絵

- **推奨: 6 つとも自前の SVG で描く**（16px、線は `currentColor`。Mermaid が描く形の輪郭をそのまま縮めたもの: 四角形は角が尖り、角丸は角が丸く、スタジアムは両端が半円、六角形は左右が尖る）。lucide の組では表せない（現況）
- SVG は `aria-hidden`（形の名は札のボタンの `aria-label` に持たせる。SVG の中に `<title>` は入れない — メニューの項目の文字と重なってテストの文字の探し方が曖昧になる）
- 同じアイコンを形のメニューの各項目にも出す（今の記号 `[ ]` などは残す）

### D5. 色と輪

- 札の地は `surface`、線と縁は `nodeBorder` 系の色の名（spec 27。新しい名が要れば data_contract `UiColorTokens` に足す）。**青（`selectionRing`・左の札の `blue.500`）は使わない**（選んだ輪と見分けがつかなくなる）
- 札の下端はノードの縁にそろえるので、選んだ輪の帯（外側 2〜5px）を札が覆う（左上の札も今そうしている）。**輪は札の所で途切れるが、ほかの 3 辺と上の縁の残りで選んだことが分かる**ことを P1 の画面で見る。
  札を輪の外まで浮かせる案（`bottom: calc(100% + 6px)`）は、ノードから離れて見えるので採らない（P1 の画面で見て、離れて見えなければこちらにする余地は残す）
- アイコンの線のコントラスト（キャンバスの地・札の地に対して 3:1 以上）は、台本ではなく**色の名の値から計算**する（spec 28 の `selectionRing` と同じ。値を data_contract に記録）

### D6. 線のボタン・回した線との重なり

- **推奨: 札は避けるものに入れない（左上の札と同じ扱い）**。回した線や線のボタンが札に重なることは許す（spec 17〜22 の golden と速さに響かせない）。
  重なった時の上下は今の層のまま（枠の無い図では札が上、枠のある図では線のボタンが上）
- 札を `RouteBox` に足して避けさせるのはスコープ外（要望があれば別の spec）

### D7. 範囲と重さ

- フローチャートのノードだけ（ER 図のテーブル・枠は形を持たない）。Web 版とデスクトップで同じ（デスクトップの差し込みは要らない, 現況）
- 形の名の文字は今は日本語のまま（UI の言語の切り替えは spec 31 で `SHAPE_OPTIONS` の名と一緒に移す）
- **札のメニューは押した時だけ差し込む**（spec 23 の線のラベルと同じ形: 閉じた札は素のボタン、押した時に閉じた `Menu` を差し込んで次の描画で開く, failures #42）を既定にする。
  P0 で、ノードごとに閉じた `Menu` を 1 つ足した時の大きな図（n57）の取り込みとドラッグの重さを測り、差が揺れの中なら素直に `Menu` を置く形に戻してよい

## 受け入れ条件（rev1）

1. フローチャートの 6 つの形のノードに、形ごとに見分けられるアイコンが出る（ライトと dark）。形を変えるとすぐ変わる
2. 札のボタンに形の名（`title`・`aria-label`）。押すと形のメニューが開き（Portal、枠の中のノードでも隠れない）、選ぶと形が変わる。札を押す・ダブルクリックしても、ドラッグやラベルの編集を始めない
3. **実画面で矩形を測って**: 札と ⋮⋮ が重ならない。長い変数名（40 字）でも左の札と右の札が重ならない
4. ノードの測った大きさ・接続点・線の回し方は前と同じ（札は線を避けさせない, D6）。選んだ輪は札の所以外で見え、選んだことが分かる
5. アイコン以外の見た目は前と同じ（spec 27 の台本でライトの計算されたスタイルを比べる。札は外枠の `Box` の**最後の子**に置いて前の要素の道筋をずらさず、札の下の要素は比べから外す）。
   アイコンの線のコントラストは色の名の値で 3:1 以上
6. 大きな図（n57）の取り込みとドラッグの重さが、前と揺れの中（裏の Edge で交互に測る, spec 22・23 の測り方）
7. テスト（vitest）: 6 つの形で印が違う（`data-shape` などで見る）・形を変えると変わる・`aria-label`・`nodrag`・ダブルクリックでラベルの編集に入らない・押すとメニューが開く（`aria-expanded` か `role="menu"` で見る。閉じた `Menu` も項目の文字を DOM に持つので文字では見ない, failures #22）・リストがノードの外（Portal）・選ぶと `onShapeTypeChange`・左の札の省略。要の分岐を壊して落ちる
8. 配布ビルドで利用者が確かめる

## Phase

- **P0**: 裏の Edge で札の実寸を測って位置を決める（D1・D3・D5）、閉じた `Menu` を足した時の重さ（D7）。data_contract に札の決まり（`NodeShapeBadge`: 位置・押した時・色の名）を書く（**台帳のコミット**）
- **P1**: アイコンの部品・右上の札・形のメニューの項目の切り出しと Portal・左の札の省略（**フォーク元の改善のコミット**）→ Web 版で裏の Edge（6 つの形・ライトと dark・矩形の重なり・輪・台本・重さ）
- **P2**: 配布ビルドで利用者が確かめる。CLAUDE.md の現状。README・README.ja の「エディタの操作」の節は次の版を出す時に足す

## スコープ外

- ノードを形どおりに描く（D1 案 C）
- 札を線のボタン・回した線に避けさせる（D6）
- 6 つより多くの形（`cylinder`・`subroutine` など。取り込みで落ちるのは今のまま）
- 形の名の翻訳（spec 31）
- フォーク元の VRT の画像の撮り直し（Lorelei では回していない。上流へ PR を出す時に撮り直す）
