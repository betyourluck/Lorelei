# Spec: 画面の言語を切り替える（日本語・英語・中国語・韓国語）

**ID**: 31
**Date**: 2026-10-30
**Status**: **Draft** — rev0（起票。D1〜D9 の裁定待ち）
**Branch**: 切らない（Phase 単位で main へ直接コミット）。画面の言葉の大半はフォーク元の部品にあるので、**フォーク元の改善（仕組み・フォーク元の言葉・Web 版の切り替え）と、デスクトップ（`lib/desktop/`・`src-tauri/`）・台帳はコミットを分け**、フォーク元のコミットだけで上流へ PR を出せる形にする（PR を出すかは利用者が決める, CLAUDE.md）

## Goal

利用者の言（2026-10-30）:

- 「UI 言語の切り替え。英語と中国語と韓国語と日本語。あまりに日本ユーザーだけだと需要が少ない」
- 「UI の切り替えは要望があれば言語を増やしていきたいので、なにか定番のライブラリを使って管理するのが良い」

画面の言葉を 4 つの言語で出し分け、利用者が切り替えられるようにする。言葉は定番のライブラリで管理し、**言語を足す時は訳のファイルを 1 つ足すだけ**にする。Web 版（ライブデモ）とデスクトップの両方。

## 現況（2026-10-30、コードを読み、数えた）

- **Rust にも画面に出る言葉がある**（`src-tauri/src/`、テスト以外）:
  - エラーの文言（`documents.rs` の「図を読めません」「保存できません」「ごみ箱へ移せません」など十数個、`lib.rs` の「図の一覧に足せませんでした」「この図の種類は GUI エディタで開けません」）。フロントはこれを画面に出す
  - 保存ダイアログの題（`desktop.rs` の「{SVG} として保存」）と About（`desktop.rs`、「Lorelei について」と説明・ライセンスの一覧）。どちらも rfd のネイティブのダイアログ

- **初期図は保険の判定に使われている**: ER 図の初期図のテーブル名は「ユーザー」（`er-diagram-editor.tsx` の `initialERNodes`）。

  AI・インポートの図を初期図で上書きする書き込みを断る保険（spec 04 D4-2・spec 08 D1、`documents.rs:221`）に使う。**初期図の言葉を言語で変えると、この保険が外れる**（failures #7 の形）。フローチャートの初期図は「Start」
- **MCP のツールの説明と AI への返事**（`crates/lorelei_mcp/src/lib.rs` の 46 行など）は日本語。読むのは AI で、画面には出ない
- **ライブラリ**（2026-10-30 に npm を見た）: `i18next` 26.5.12（2026-10-30）・`react-i18next` 17.1.9（2026-10-25、peer は `react >= 16.8`・`i18next >= 26.2`）・`next-intl` 4.14.9（peer に `next ^14`・`react ^18` を含む）。

- **画面の色の切り替え**（spec 27）はタイトルバーの「?」の左のメニュー（`lib/desktop/color-mode-menu.tsx`）で、yamada-ui が localStorage の `ui-color-mode` に覚える。Web 版には切り替えを出していない（spec 27 の裁定）
- README は英語（`README.md`）と日本語（`README.ja.md`）

## 決めること

### D1. ライブラリ

- **案 A（推奨）: `i18next` + `react-i18next`** — React の i18n で最も広く使われる組。ブラウザの中だけで動くので、静的な書き出し（`output: "export"`、Web 版も Tauri も）と相性が良い。
  複数形・差し込み（`{{count}}`）・言語が無い時の代わりの言語を持つ。TypeScript でキーを型にでき（`CustomTypeOptions` の `resources`）、無いキーは `tsc` で落ちる
- 案 B: `next-intl` — Next の App Router 向けで、言語ごとの URL（`/en/…`）かサーバー側の設定が前提。静的な書き出しでは言語ごとにページを書き出すことになり、Web 版の URL が変わる。採らない
- 案 C: Lingui・FormatJS（`react-intl`）— Lingui は文の取り出しにコンパイルの段（Next 14 の SWC の plugin）が要る。FormatJS は使えるが、広さで i18next に劣る
- 版は**出てから 2 週間以上たったものに固定**する（細かく出ているため。P0 で選び、`package.json` に `^` を付けずに書く）

### D2. 訳のファイルの形

- **推奨**: `locales/{ja,en,zh-Hans,ko}.json`（言語ごとに 1 ファイル、キーは場所ごとの入れ子: `toolbar.confirm`・`node.shape.diamond` など）。4 つとも組み立てに同梱する（デスクトップはネットにつながらない前提、言葉は全部で数十 KB）。
  **言語を足す時は JSON を 1 つ足し、言語の一覧（1 か所）に 1 行足すだけ**にする
- テストで、全部の言語が日本語と同じキーの組を持つことを確かめる（足りないキーは言語が無い時の代わり = 英語に落ちるが、テストは赤にする）
- 直に書いた日本語が残っていないことをテストで見る（コメント・テスト・訳のファイル・認めた例外 — 初期図・Mermaid の例文など — を除いて 0 行）

### D3. 言語

- **推奨**: 日本語（`ja`）・英語（`en`）・中国語の簡体字（`zh-Hans`）・韓国語（`ko`）。繁体字（`zh-Hant`）は要望があれば足す（D2 の手順で）

### D4. 最初の言語と覚え方

- **推奨**: 選んだ言語を覚えていればそれ → 無ければ OS（ブラウザ）の言語（`navigator.languages` を上から見て、`zh-CN`・`zh-SG` → `zh-Hans`、`ko-KR` → `ko` のように近いもの）→ 合うものが無ければ英語
- 覚える場所は localStorage（`lorelei.locale.v1`）。画面の色（yamada-ui の `ui-color-mode`）と同じく、デスクトップは WebView の localStorage
- 切り替えたら開き直さずにすぐ全部の言葉が変わる。`<html lang>` も変える

### D5. 切り替えの置き場所

- **推奨**: デスクトップはタイトルバーの画面の色のメニューの隣に地球のアイコン（`languages`）のメニュー。Web 版はフォーク元の見出し（`components/ui/navigation-menu.tsx` の並び）に同じメニュー
- 言語の名はその言語で書く（日本語・English・简体中文・한국어）

### D6. Web 版

- **推奨: Web 版（ライブデモ）にも出す**。利用者を増やす目的（Goal）では、最初に触るのがライブデモなので。URL は変えない（言語ごとの URL にしない、D1）

### D7. Rust の言葉

- **推奨**:
  - **エラーは「コード + 値」で返し、フロントで訳す**（例 `{ code: "DOCUMENT_READ_FAILED", detail: "…" }`）。今の文字列の頭で見分けている `INITIAL_FIGURE_REJECTED`・`STALE_BASE`・`DOCUMENT_GONE` も同じ並びに入れる
  - **保存ダイアログの題と About の文言は、フロントが訳して Rust に渡す**（今は Rust が日本語で持つ）
  - **新しい図の題**: Rust は今の言語を知らないので、フロントが選んだ言語を Rust に知らせ（`set_ui_locale`、`{app_data_dir}/ui_locale.json` に覚える）、`default_title` を 4 つの言語の表で引く。AI が題を付けずに届けた図も、覚えた言語で付く（一度も知らされていなければ英語）。
    すでにある図の題は変えない（ファイルに残った題は利用者の持ち物）
  - Rust に i18n の crate は足さない（言葉は十数個で、表で足りる）
- 案: Rust 側も crate（`rust-i18n` 4.2.4）で訳のファイルを持つ — フロントと Rust で訳が 2 か所に分かれる。採らない

### D8. 初期図

- **推奨: 初期図は言語で変えない**（保険の判定 = 現況）。ER 図の初期図のテーブル名は、どの言語でも読める **`User`** に変える（`initial_source` と vitest の突き合わせも同じに変える）。
  前の初期図（「ユーザー」）で書かれたままの図も保険が効くよう、`initial_source` は前の形も初期図と見なす（P0 で、前の形を残す必要があるかを `first_fill` の条件から確かめる）
- 案: 初期図も言語ごとに出し分け、Rust の保険は全部の言語の初期図を知る — 言語を足すたびに Rust の表も要る。採らない

### D9. 訳の質と範囲外

- 英語・中国語・韓国語の訳はこちらで作る。**中国語と韓国語は母語の人が確かめていない**ことを README（英語・日本語）に書き、直しを Issues で受ける（CONTRIBUTING に手順）
- 画面に出ないもの — **MCP のツールの説明と AI への返事**（読むのは AI）・コードのコメント・ログ — は訳さない（スコープ外）
- Mermaid の補完の説明（`mermaid-completion.ts`）は画面に出るので訳す。Mermaid の記法そのもの（キーワード・例のコード）は訳さない
- 日付と時刻（図の一覧の時刻など）は `Intl` に選んだ言語を渡して書く

## 受け入れ条件（rev0）

1. 4 つの言語に切り替えられ、開き直さずに画面の言葉がすべて変わる（デスクトップの外枠・2 つのエディタ・ダイアログ・設定画面・About・保存ダイアログの題・エラー。Web 版も）
2. **日本語の画面は前と同じ**（spec 27 の台本で、ライトの計算されたスタイルと文字が前の記録と一致する）
3. 選んだ言語は開き直しても残る。覚えていない時は OS の言語、合わなければ英語
4. 全部の言語が同じキーの組を持つ（テスト）。直に書いた日本語が、認めた例外を除いて 0 行（テスト）
5. 英語・中国語・韓国語で、文字が長くなっても部品からはみ出さない・重ならない（台本の場面ごとに裏の Edge で撮って見る）
6. 初期図の保険が前と同じに効く（Rust・vitest）。新しい図の題が選んだ言語で付く
7. 配布ビルドで利用者が確かめる

## Phase

- **P0**: 言葉を全部数える（`aria-label`・`title`・`placeholder`・Rust のエラーとダイアログ、例外の一覧）、版を選ぶ、キーの名の付け方、D8 の保険の前の形。data_contract の名詞を凍結（`UiLocale`・`UiMessages`・Rust のエラーのコードの一覧など）
- **P1**: 仕組み（i18next・言語の判定・覚える・`<html lang>`・キーの型・テスト 2 つ）とフォーク元の言葉を日本語の JSON へ移す・Web 版の切り替え（**フォーク元の改善のコミット**）→ 日本語の画面が前と同じことを台本で
- **P2**: デスクトップ — `lib/desktop/` の言葉・タイトルバーの切り替え・Rust のエラーのコード・保存ダイアログの題と About・`set_ui_locale` と新しい図の題・初期図（D8）→ `tauri dev` で確かめる
- **P3**: 英語・中国語・韓国語の訳 → 4 つの言語で台本の全部の場面を撮り、はみ出し・重なりを直す
- **P4**: 配布ビルドで利用者が確かめる。README（英語・日本語）に言語の切り替えと訳の確かめの状態、ライブデモを作り直す

## スコープ外

- 繁体字ほかの言語（D2 の手順で足せるようにしておく）
- MCP のツールの説明・AI への返事の訳（D9）
- README・LORELEI.md・CONTRIBUTING の中国語・韓国語の版
- 右から左へ書く言語（アラビア語など。並びの反転が要る）
