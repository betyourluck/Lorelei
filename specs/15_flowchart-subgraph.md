# Spec: フローチャートのサブグラフをエディタで扱う（枠として表示し、保存で落とさない・GUI で編集する）

**ID**: 15
**Date**: 2026-09-30
**Status**: rev2（P0 結果を反映。裁定 1〜5 済み。P1 に着手できる）
**Branch**: 切らない（Phase 単位で main へ直接コミット）。ただし**フォーク元の改善とデスクトップ・Rust・台帳はコミットを分け**、フォーク元のコミットだけで上流へ PR を出せる形にする
（CLAUDE.md のとおり、フォーク元の改善のコミットは `lib/desktop/` と台帳（data_contract・specs・CLAUDE.md・failures）を含まない。同じ Phase の中でもコミットを分ける）

## Goal

AI が書いた（あるいはインポートした）フローチャートの `subgraph` を、**エディタで枠として表示し、保存・`read_diagram`・コード生成で落とさない**。
そのうえで、人が GUI で枠を作る・ノードを枠に出し入れする・枠の題を変える・枠を消すことができるようにする。

今は取り込みの段階でサブグラフを数えて捨てている（中のノードと線は取り込む）。AI が「受付」「審査」のように段を分けて書いた図は、
デスクトップで開いて 1 秒後の自動保存で枠が消え、`read_diagram` で読み戻しても戻らない（LORELEI.md 既知の制約）。
GUI の書き出しボタン（SVG / PNG / PDF）も生成器の出力を描くので、手直しした図を書き出すと枠が無い。
北極星（AI が書いた Mermaid を、そのまま使える図にする）に対して、落ちる要素のうち最も目に見えるもの。

**フォーク元の改善**（Web 版のインポート・コード生成も同じく落とす）なので、上流へ返せる形にする（掟。Branch の行）。

## 裁定（2026-09-30、利用者）

- **裁定 1（D3）**: 取り込み時の配置は今の段組みを入れ子に使う（案 A。dagre・ELK は入れない）
- **裁定 2（D5）**: 枠は「枠を追加」で空の枠を置き、ノードをドラッグで入れる（案 A。「枠で囲む」は入れない）
- **裁定 3（D5）**: 枠を消す時は枠だけ消し、中のノードは外側の枠（無ければ図の直下）へ移して残す（案 A）
- **裁定 4（D7、P0 の後）**: 空の枠は裁定 2 のまま書き出し、描画では四角いノードになることをエディタとコード生成のダイアログで知らせる（案 A）
- **裁定 5（D8、P0 の後）**: ノードと線のラベルの `direction` の穴は spec 15 の P1 で、フォーク元の改善の別のコミットとして直す（案 A）

### エディタ・生成器・配置

- ノードの種類は `editableNode` の 1 つだけ（`features/flowchart/components/node/node-types.tsx`）。新しいノードの ID は数字、変数名は `node{ID}`（`hooks/flow-helpers.ts:42・47`）
- `@xyflow/react` は **12.8.2**（`@xyflow/system` 0.0.66）で、サブフロー（`parentId`・子の位置は親からの相対・`extent: "parent"`・`expandParent`）を持つ。
  ドラッグでの親の付け替えは自動ではしない（ドロップ時に重なりを調べて自前で付け替える）。**`expandParent` はドラッグ中にも効き**、子を枠の端へ動かすと枠が広がる（system の drag の処理）
- **xyflow の削除は、親を消すと子も一緒に消す**（system の `getElementsToRemove` が `parentId` が消す側にあるノードを足す）。Backspace も `deleteElements` も同じ経路で、`onBeforeDelete` はその足された後の一覧を受け取る
- 生成器 `generateMermaidCode`（`hooks/mermaid.ts:256`）はノードの定義を全部並べてから線を全部並べる。サブグラフを書く口は無い
- 取り込み時の配置は `flow-editor.tsx:340` の自前の段組み（入る線の無いノードを根に段を数え、向きに沿って段を並べる。段は最長の道で決まり、同じ組の線が何本あっても段は変わらない）。枠を知らない。
  配置のライブラリは入っていない（`dagre-d3-es` は mermaid の依存としてあるだけ）

### 保存（デスクトップ）

- `Document.source` は生成器の出力、`Document.layout` は `{ Mermaid 上の ID: { x, y } }`（`lib/desktop/doc-session.ts:26` の `collectLayout` が `node.position` をそのまま集める）。
  **子ノードの `position` は親からの相対**になるので、今の `collectLayout` のままでは枠に入ったノードの位置が相対で保存される
- 位置を当てる合図 `layoutReady` は、開く図のキー（`expectedKeys`。`data.nodes` の変数名）がストアに全部そろった時に立つ（`doc-session.ts:36〜60`）。枠のキーは今は入らない
- Rust の `Pos` は `{ x: f64, y: f64 }` だけ（`src-tauri/src/documents.rs:30`、`deny_unknown_fields` は無い）。serde は知らないフィールドを黙って読み捨てるので、
  **枠の大きさ（幅・高さ）を足しても Rust を通ると失われる**（止まりはしない）

## 決めること

### D1. データの形

- `ParsedMermaidData` に `subgraphs?: ParsedMermaidSubgraph[]` を足す（無ければ今と同じ）。`ParsedMermaidSubgraph = { id, title, nodes: string[], parent?: string }`。
  `nodes` は直下のノードの ID だけ（入れ子の枠は子の枠の `parent` で表す）
- **1 つのノードの親は 1 つ**（xyflow の `parentId` も 1 つ）。P0 で、mermaid.js と merman は**どちらも**、1 つのノードを 1 つの枠にしか入れないと分かった（先に `end` で閉じた枠が取る）。
  取り込みは両方の `nodes` の一覧をそのまま読めばよく、揃え直しは要らない
- 枠の `nodes` の一覧には、**子の枠の ID も入る**（P0）。枠の親は「自分の ID を `nodes` に持つ枠」。自分自身を `nodes` に持つ枠（`subgraph X` の中に `X`）は、その 1 件を無視する（親子が輪になるため）
- エディタでは枠を**新しいノードの種類 `subgraphNode`**（xyflow の親）にし、中のノードに `parentId` を付ける。xyflow の決まりで親は子より前に並べる —
  **`getSubGraphs()` の順番に頼らず、`parent` を辿って親から順に並べ直してからノードにする**（P0: 両方の実装とも**内側の枠が先**に並ぶので、並べ直しは必須。
  xyflow は親が後ろにあると子の位置を計算せず警告だけ出す）
- 枠の `data` は `variableName`（Mermaid 上の ID）と `title` を持つ。`doc-session.ts` の `keyOf` は枠も `variableName` で呼ぶ（ノードと同じ）
- 枠の ID とノードの ID は同じ名前空間。**取り込み時にぶつかった時**（P0: 両方の実装とも誤りにせず、同じ ID のノードと枠の両方を作る。線が枠を指した時も、その ID のノードができる）は、
  **今の取り込みと同じ**にする: 枠の ID と同じ ID のノードは作らず、それにつながる線は `edge_to_subgraph` として落とす。生成器は枠の ID にも `getSafeVariableName` を通す
- data_contract: `ParsedMermaidData`・`EditorPayload.mapping.flowchart`（`subgraph` の行を落とす側から写す側へ）・`dropped_constructs` を直す（書く Phase は下の「Phase」）

### D2. 生成器の書き方（往復が mermaid.js と merman の両方で戻ること）

- 枠のあるノードは `subgraph <ID>["<題>"]` … `end` の中に定義を書き、入れ子は入れ子に書く。枠の無いノードは今までどおり外に書く
- **題は ID と同じでもいつも `["…"]` で書く**（省く規則を持たない。比べる時期で出力が揺れるのを避ける）。`<ID>` と `[` の間に空白は入れない（P0: あり・なしどちらも両方の実装で同じに読む）
- **題の囲み**（P0 で固定）: ノードのラベルの `escapeQuoted`（`#語;` の `#` を `#35;`、`"` を `#quot;`）に、
  **`direction` + 空白 + 向きの空白を `#32;` にする**（spec 13 D1 の ER 図と同じ置き換え）を足す。空の題は `" "`（`""` は mermaid.js で誤り、`" "` は両方で空の題になる）。
  P0 の題の格子 27 通り（括弧・`|`・`:`・`;`・`end`・`subgraph`・`-->`・HTML・`%%`・バックスラッシュ・タブ・全角数字 …）は、この囲みで両方の実装が同じ題に戻す
- **線は全部、最後に外へ書く**（P0: ブロックの中に書いた線は外のノードを引き込む。外に書けば、枠の中のノードは両方の実装で枠に留まり、merman の描画でも枠の中に描かれた）
- **空の枠**は両方の実装で枠として残る（`nodes: []`）。ただし**描画では枠ではなく、題を書いた四角いノードになる**（P0: mermaid.js も merman も。子の無いクラスタは普通のノードの道へ回る）。扱いは **裁定 4**（下）
- **枠の無い図の出力は一字一句変えない**（`initial_sources.flowchart` の突き合わせ, spec 04 D4-2 と、保存済みの図の揃え書きを起こさないため）

### D3. 取り込み時の配置（**裁定 1: 今の段組みを入れ子に使う**）

- 内側から順に、枠の中を今の段組みで並べ、中身の外接矩形に余白と見出しの高さを足して枠の大きさを決める。外側では枠を 1 つのノードとみなして同じ段組みで並べる
- **枠をまたぐ線は、両端の「同じ枠の中で並んでいる祖先」どうしの線とみなす**（ノード A（枠 X の中）→ ノード B（枠 Y の中）で、X と Y が同じ階層なら X → Y。
  片方が外側の階層にいるなら、その階層まで持ち上げる）。同じ組の線は 1 本にまとめる（今の段組みは段を最長の道で決めるので本数は段に効かないが、組を数える処理を軽くするため）。
  自分の祖先を指す線（枠の中のノード → その枠自身の外のノードへ持ち上がって同じ点になるもの）は配置では無視する
- 枠の無い図の配置は今と変わらない（受け入れ条件 3）

### D4. 保存（デスクトップ）

- `Document.layout` の値に `width?` / `height?` を足す（枠だけが持つ）。キーは Mermaid 上の ID（枠の ID も入る）。Rust の `Pos` にも `Option` で足し、`None` は書かない（`skip_serializing_if`）
- **位置は絶対座標で保存する**。入れ子に対応するため:
  - `collectLayout`: ノードの絶対位置 = 自分の `position` + 祖先の `position` を**根まで累積**した和（親を辿る。親の ID が見つからない時は辿るのをやめる）
  - `withLayout`: **親から順に**（D1 の並べ直した順）絶対位置を決め、子の `position` = 子の絶対位置 − 親の絶対位置
  - ノードを枠から出し入れしても、保存した位置の意味が変わらない
- `expectedKeys` に `data.subgraphs` の ID も入れる（枠の位置と大きさも、ノードと同じ合図で当てる）
- 位置の無い枠は D3 の配置で置く
- 新旧の組み合わせ:

  | 書いた側 → 読む側 | 結果 |
  |---|---|
  | 今の版のファイル → 新しい版 | そのまま読める（`width` / `height` 無し = 枠は D3 の大きさ） |
  | 新しい版のファイル → 新しい版 | 位置と大きさが戻る |
  | 新しい版のファイル → 今の版（戻した時） | 止まらない。`source` の `subgraph` は今の版の取り込みで落ち、枠の大きさは読み捨てられる。次の自動保存で枠は消える（今の版の既知の制約のまま。戻すことは想定しない） |

### D5. GUI の編集（**裁定 2・3**）

- **「枠を追加」**（裁定 2）: 空の枠を今の画面の中央に置く。初期値は ID `group{N}`（N は使っていない最小の番号）、題 `グループ{N}`、大きさ 320×200（ノード 1 つと余白が入る。P1 で画面を見て直す）。
  P0 で `group1`・`subgraph1`・`end1`・`direction1`・`graph1` はどれも両方の実装で 1 つの ID として通った（キーワードで割れる恐れは無かった）。ノードの `node{N}` に揃えた短い英語として `group{N}` のままにする
- **枠の背景は半透明にする**: xyflow は子ノードにつながる線を子と同じ高さ（親 + 1）へ上げるが、**枠の外どうしを結ぶ線が枠の上を横切る時は枠の下に描く**（`getElevatedEdgeZIndex`）。不透明だと線が隠れる
- **出し入れ**: ドラッグ中は `extent: "parent"` も `expandParent` も**使わない**（使うと枠の外へ出せない・出そうとすると枠が広がる）。**ドロップした時に**判定する:
  - ノード（または枠）の中心を含む枠のうち、一番内側のものを新しい親にする。どの枠にも入らなければ図の直下
  - **自分自身と自分の子孫の枠は、新しい親の候補から外す**（外枠を内枠の中へ落として親子が輪になるのを防ぐ。輪は D4 の累積・生成器の入れ子・xyflow の描画のどれも止める）
  - 親が変わらず、枠の端からはみ出しただけなら、枠を中身に合わせて広げる（自前で。はみ出した分だけ）
  - 座標は相対 ↔ 絶対に直す（D4 と同じ計算）
- **題**: 枠の見出しをダブルクリックで編集（ノードのラベルと同じ操作）。**ID** は変数名の欄（ノードと同じ, `variable-name-editor.tsx`）。ノード・ほかの枠の ID とぶつかる名前は確定させない
- **大きさ**: xyflow の `NodeResizer`。中身より小さくはできない
- **消す**（裁定 3）: xyflow は親を消すと子も消す（現況）ので、`onBeforeDelete` で**消す一覧から子を外し、子を先に付け替えてから**枠を消す。
  - 付け替え先は、消す枠の親（無ければ図の直下）。**子の枠も同じく 1 段上へ移る**（中身ごと。再帰して平らにはしない）。位置は絶対のまま変えない
  - 枠と中のノードを一緒に選んで消した時は、選んだものは全部消える（利用者が選んだものを消す。付け替えは選ばれていない子だけ）
  - 確認のダイアログは spec 06 と同じく出す。文は「枠『受付』を削除しますか？ 中のノード 3 個は残ります」のように、残るものを書く
- **デスクトップのツールバー**: 「枠を追加」を `useDesktopActions` に足す。これは `lib/desktop/` の変更なので、**P3 の中でフォーク元のコミットとは別のコミットにする**（spec 11 D7 と同じ）。
  デスクトップはフォーク元のパネルを隠しているので、フォーク元の部品を直したら、デスクトップのどの操作がどの部品を開くかを grep で確かめる（failures #17）

### D6. 落とし続けるもの（知らせ方は今のまま）

- サブグラフを指す線（`edge_to_subgraph`）・サブグラフの中の `direction`（新しい construct `subgraph_direction`）は P5 まで落として数える
- 要約と黄色の印（`drop-warnings.ts`）は、`subgraph` / `end` の行に印を付けるのをやめ、サブグラフを指す線と中の `direction` の行に付ける
- LORELEI.md の既知の制約から subgraph を外し、残る 2 つを書く

### D7. 空の枠の描かれ方（**裁定 4: 案 A**）

P0 で、空の枠は Mermaid の描画（mermaid.js・merman とも）で枠ではなく四角いノードになると分かった。データ（保存・`read_diagram`・取り込み）では枠として残る。案:

- **案 A（推奨）: 裁定 2 のまま。エディタの空の枠に「空の枠は、書き出すと四角いノードとして描かれます」と薄く書き、コード生成のダイアログにも出す** — 置いてから入れるまでの一時の状態なので、編集の操作は変えない。往復は保たれる
- 案 B: 空の枠は書き出さない（生成器が飛ばす）— 描画の食い違いは無くなるが、保存すると空の枠が消え、「枠を追加」した直後の自動保存で枠が消える。裁定 2 と合わない
- 案 C: 裁定 2 を「枠で囲む」に替える（空の枠を作らせない）— 取り込んだ図の空の枠は残るので、食い違いは消えない

### D8. ノードと線のラベルの `direction`（今の生成器の穴。**裁定 5: 案 A**）

P0 の題の格子で、mermaid.js の字句解析が `direction` + 空白 + 大文字の向き（`TB` `BT` `RL` `LR` `TD`）を**行のどこにあっても**、囲みの中でも拾い、そこから行末までを向きの指定として取ると分かった。
**ノードのラベル・線のラベルに `direction LR` を含むと、mermaid.js ではその行のノードと線が誤りも出さずに消える**（`A["x direction LR"] --> B[b]` は A も B も線も無くなる）。merman は正しく読む。
今のフォーク元の生成器（spec 11 D5 の `quoteNodeLabel`）はこれを避けていないので、**Web 版のインポート・コード生成のプレビュー・デスクトップのインポート（TS の取り込み）で、そのノードが黙って消える**。小文字の `lr` は当たらない。
空白を `#32;` にすれば両方の実装で通り、元の文字に戻る（P0）。

- **案 A（推奨）: P1 に、別のコミット（フォーク元の改善）で入れる** — 題の囲み（D2）と同じ置き換えなので、同じ関数をノードのラベル・線のラベルにも通す。数行の直しとテスト
- 案 B: 別の spec にする（spec 15 は枠だけ）

## Phase

- **P0（リサーチ、コードは変えない）**: 使い捨てのテストで mermaid.js 11.17.2 と merman の両方に通し、結果を「P0 結果」に表で書く。**全部が必須**:
  1. 書き方の格子: `subgraph id` / `subgraph id[題]` / `subgraph id [題]` / `subgraph id["題"]` / `subgraph id ["題"]` / `subgraph 空白を含む題`、題の特殊文字（spec 13 の格子を流用）

  3. 1 つのノードが 2 つのブロックに出る時の所属、外で定義したノードをブロックの中で参照した時

  5. **空の枠**が枠として残るか
  6. 枠の ID とノードの ID の衝突（同じ名前のノードと枠・線が枠の ID を指す）
  7. `group1`・`subgraph1`・`end1` のような、キーワードで始まる ID と始まらない ID
  8. xyflow 12.8.2: 親子の並び順・相対座標・枠の上に線が隠れないか（z の順）・`NodeResizer`・ドラッグ中の `expandParent`・親を消した時の子

- **P1（フォーク元）**: 型・TS の取り込み（親から順に並べ直す）・`subgraphNode`（表示だけ。枠ごと動く。空の枠の注記 D7）・D3 の配置・生成器（D2）・要約と印（D6）。

  **別のコミットで台帳**: data_contract の TS の側（`ParsedMermaidData`・`EditorPayload.mapping.flowchart`・`dropped_constructs`）と spec の結果
- **P2（デスクトップ・Rust）**: Rust の `to_editor` が `subgraphs` を返す・TS の生成器の出力を fixture にして Rust に通す（spec 13 P3 と同じ流儀）・
  `Document.layout`（D4: 絶対座標の累積・大きさ・`expectedKeys`・Rust の `Pos`）・MCP の `open_in_editor` / `read_diagram` / `update_diagram` の往復・LORELEI.md。
  data_contract の Rust と Document の側。`tauri dev` で確かめる
- **P3（フォーク元 + デスクトップの別コミット）**: GUI の編集（D5）。削除の確認（spec 06）との合わせ。デスクトップのツールバーの「枠を追加」は別のコミット
- **P4（配布ビルド）**: AI が書いた枠つきの図を MCP で開き、手で直し、`read_diagram` で枠が残ることを見る。画面は利用者のスクリーンショットで受け取る（failures #17）
- **P5（任意。P4 の後に続けるか利用者が決める）**: サブグラフを指す線・サブグラフの中の `direction`

## 受け入れ条件

1. 枠つきのフローチャートを MCP・インポートで開くと、枠が題つきで表示され、中のノードが枠の中に並ぶ（入れ子も）。枠を動かすと中も動く
2. 開いた図を保存・`read_diagram`・コード生成・GUI の書き出しにかけると、`subgraph` … `end` が残り（書き出しは枠が描かれ）、mermaid.js と merman の両方で同じ枠と中身に読める（空の枠も）
3. 枠の無い図の生成器の出力と取り込み時の配置は今と変わらない（初期図の突き合わせのテストが通る）
4. 枠の位置と大きさは、図を切り替えて開き直しても戻る。枠から出し入れしたノードの位置も戻る（入れ子の中のノードも）
5. GUI で枠を作る・ノードや枠を入れる・出す・題を変える・大きさを変える・消す（中身が残る）ができ、その結果が 2 のとおりに書き出される。枠を自分の子孫の中へ落としても親子は輪にならない
6. 落とし続けるもの（サブグラフを指す線・中の `direction`）は、取り込み前の要約・行の印・MCP の戻り値で知らせる
7. Web 版（GitHub Pages）のフローチャートのエディタで 1・2（コード生成まで）・5 ができる（デスクトップ専用の変更を含まない）

## スコープ外

- ER 図のサブグラフ（spec 11 のまま、関係を落として数える）
- `classDef` / `class` / `style` / `linkStyle`（枠の色を含む）
- サブグラフを指す線・サブグラフの中の `direction`（P5 で扱うかは利用者が決める。扱わない時は次の spec の候補）
- 選んだノードを「枠で囲む」操作（裁定 2 で採らなかった）
- 書き出し（SVG / PNG / PDF）の仕組みは変えない。MCP の `render` は AI の原文を描くので今も枠が出る。
  GUI の書き出しボタンはコード生成のダイアログのコード（生成器の出力, `download-modal.tsx:68`）を渡すので今は枠が落ちるが、D2 で生成器が枠を書けば直る（受け入れ条件 2 に含まれる）
