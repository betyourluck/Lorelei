# Spec: 操作を元に戻す・やり直す（Undo/Redo）と、最後の「確定」へ戻す

**ID**: 30
**Date**: 2026-10-30
**Status**: **Draft** — rev0（起票。D1〜D7 の裁定待ち）
**Branch**: 切らない（Phase 単位で main へ直接コミット）。Undo/Redo はエディタ（フォーク元の部品）の改善なので、**フォーク元の改善と台帳・デスクトップはコミットを分け**、フォーク元のコミットだけで上流へ PR を出せる形にする（PR を出すかは利用者が決める, CLAUDE.md）。
「確定へ戻す」はデスクトップ専用（`lib/desktop/`・`src-tauri/`）

## Goal

利用者の言（2026-10-30）: 「確定ボタンを押される前に戻すボタンが欲しい（やり直し）UndoRedo。現在では確定ボタンはほとんど意味をなしていない。せめて確定するまえに戻せるなどがよい」

1. エディタの操作を 1 手ずつ元に戻す・やり直せるようにする（Web 版とデスクトップ）
2. デスクトップで「確定」を**戻れる区切り**にする: 最後に確定した時の中身へ戻せるようにする

## 現況（2026-10-30、コードを読んだ）

- **エディタに元に戻す仕組みは無い**: `undo` / `redo` / `history` を持つのは CodeMirror（`components/ui/code-editor.tsx` の `history()`・`historyKeymap`、インポートとコード生成のダイアログの中）だけ。
  キャンバスで Ctrl+Z を押しても何も起きない
- **エディタの状態**: 2 つのエディタとも xyflow の `useNodesState` / `useEdgesState` で持つ（`flow-editor.tsx:112-113`・`er-diagram-editor.tsx:93-94`）。
  変える入口はフローチャートで、ラベル・変数名・形・枠の題・枠の向き（`relayoutFrame` で中を並べ直す）・ノードの削除（`onBeforeDelete` の確認を通る）・線のラベル・線の削除・矢印・つなぐ（`onConnect`）・何も無い所へ離して新しいノード（`onConnectEnd`）・ノードと枠の追加・ドラッグ（`onNodeDragStop` で枠への付け替え）・インポート・図の向き・テーマ。
  ER 図は、テーブルの追加・削除、テーブルの中（名前・列・PK/UK/FK）、関係のラベル・多重度・削除、つなぐ、インポート。テーブルの中の編集がどこから `setNodes` するかは P0 で数える
- **ノードと線の `data` に関数が入っている**: `onDelete`・`onLabelChange` などのハンドラを `data` に持たせている（`flow-editor.tsx` の 267・293・309・387・431・646・664・679 行など）。
  状態をそのまま写して戻すと、古い関数が残る（戻す時に今のハンドラを付け直す必要がある）
- **「確定」**（spec 02 D12、2026-10-04 に「保存」から改名）: `mark_document_saved` が `saved_at` を書き、一覧の先頭へ上げて ● を消すだけ。**確定した時の中身は残していない**。
  中身は 1 秒の自動保存（`use-doc-session.ts` の `AUTOSAVE_DELAY_MS = 1000`）で `source` と `layout` に常に書かれている
- **残っている過去の版**: AI の `update_diagram` が書き換える前の 1 世代だけ（`{app_data_dir}/history/{id}.json`, spec 08 D5。GUI からは戻せない、戻すのは人が手で）
- **AI の書き換えの載せ替え**: 開いている図に `update_diagram` が届くと、書きかけを捨てて届いた中身をエディタに載せ直す（`use-doc-session.ts` の `reloading`, spec 08 D3）

## 決めること

### D1. 1 手と数えるもの

- **推奨**: 図の中身（ノード・線・枠・ラベル・形・向き・テーマ・位置）を変える操作 1 回を 1 手とする
  - ドラッグは**手を離した時に 1 手**（複数を選んでまとめて動かしても 1 手。枠への付け替えも同じ手）
  - ラベル・変数名・枠の題は**入力を確かめた時（Enter・フォーカスが外れた時）に 1 手**（1 文字ずつではない）
  - 枠の向きの変更と、それによる中の並べ直し（spec 16 P5）は 1 手
  - 削除で確認を出す操作（spec 06）は、確認で「削除」を押した時に 1 手（やめたら手にならない）
  - 選ぶ・画面を動かす・拡大は手にしない
- インポート（図を丸ごと置き換える）も 1 手（戻すと取り込む前の図に戻る）

### D2. 押し方

- **推奨**: Ctrl+Z で戻す、Ctrl+Y と Ctrl+Shift+Z でやり直す（Mac は ⌘）。
  **文字の入力欄（ラベル・変数名・テーブルの中の欄・CodeMirror など）にフォーカスがある時は、その欄の取り消しに任せて図の Undo はしない**
- ボタン: デスクトップはツールバーに ↶ ↷（`useDesktopActions` に `undo` / `redo` と押せるかを足す。デスクトップはフォーク元のパネルを隠すので）。
  Web 版はフォーク元のパネルに同じボタン。戻せる手が無い時は押せない

### D3. 履歴の持ち方

- **推奨**: エディタごとに、画面の中だけで持つ（ファイルには書かない）。上限 100 手（古いものから捨てる）。
  **別の図を開いた時（デスクトップ）・アプリを閉じた時に捨てる**。新しい手を打つと、やり直せる手は消える（ふつうの Undo と同じ）
- 戻した結果も自動保存で `source` と `layout` に書かれる（今の自動保存の経路のまま）。● は内容が確定と違えば付く（今の `unsaved` の規則のまま）

### D4. AI の書き換え（`update_diagram`）の載せ替え

- **案 A（推奨）: 1 手として記録する**（戻すと AI が書き換える前の図に戻る。「AI の変更を取り消したい」に直接答える）。
  戻した結果は自動保存で書かれ、`updated_at` が進む。AI が次に読まずに `update_diagram` すると、今の楽観ロック（`expected_updated_at`, spec 08 D2）で断られ、読み直しを求められる（今の規則のまま）
- 案 B: 載せ替えで履歴を捨てる — 単純だが、AI の変更は D5 の「確定へ戻す」でしか戻せない
- 載せ替えは取り込み・位置の当て直しが数段に分かれる（`use-doc-session.ts`）。**載せ終えた後の 1 回だけを手にできるかを P0 で確かめ**、できなければ案 B に落とす

### D5. 「確定へ戻す」（デスクトップ）

- **推奨**: 「確定」を押した時に、その時の `source` と `layout` を図の中に残す（`Document.confirmed: { source, layout, saved_at }`、`documents/{id}.json` の中。ごみ箱へ移す時も一緒に動く）。
  ツールバーの「確定」の隣に「確定へ戻す」を置き、押すと確認を出してから、残した中身をエディタに載せ直す（戻す操作自体も 1 手なので Undo で取り消せる）
- 押せるのは、確定したことがあり、確定の後に変更がある（●）時だけ。一度も確定していない図では押せない（`title` で理由を出す）
- 作った・取り込んだ・AI が届けた時の中身（`original_source`）へ戻す案は入れない（`original_source` は位置を持たず、`update_diagram` で上書きされる）
- MCP には何も足さない（`read_diagram` は今の中身を返す。`confirmed` は返さない）。`update_diagram` は `confirmed` を変えない

### D6. 範囲

- Undo/Redo: 2 つのエディタ。Web 版とデスクトップで同じ（エディタはフォーク元の部品）
- 「確定へ戻す」: デスクトップだけ（Web 版には「確定」が無い）

### D7. 作り方（P0 で決める）

- 案 A: 手ごとに `nodes` / `edges` を写して持ち、戻す時に今のハンドラを `data` に付け直す（現況の関数の問題）。xyflow の測った大きさ（`measured`）は写さない
- 案 B: 手ごとに生成器の出力（Mermaid の本文）と位置（`collectLayout`）を持ち、開く時と同じ経路で載せ直す — 関数の問題は無いが、生成器が落とすもの（エディタだけが持つ状態）があれば戻らない
- **P0 で、両方を 2 つのエディタの全部の入口で試し**、戻した後の図が前と同じか（生成器の出力・位置・枠の親子）と、1 手を記録する時間を測ってから決める

## 受け入れ条件（rev0）

1. D1 の全部の操作が、2 つのエディタで 1 手ずつ戻り、やり直せる（戻した後の生成器の出力・位置・枠の親子が、その手の前と同じ）
2. Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z とボタンで動く。文字の入力欄の中では図の Undo をしない
3. 戻した結果が自動保存され、開き直しても戻した中身が出る（デスクトップ）
4. 「確定へ戻す」で最後に確定した中身と位置に戻り、それも Undo で取り消せる。確定したことの無い図・変更の無い図では押せない
5. （D4 案 A なら）AI の書き換えを 1 手で戻せ、その後の AI の `update_diagram` は楽観ロックで断られる
6. テスト（vitest・Rust）: 手の記録と戻し・入力欄の中の Ctrl+Z・上限・`confirmed` を書く時と戻す時。要の分岐を壊して落ちる
7. 配布ビルドで利用者が確かめる

## Phase

- **P0**: 入口を全部数える（2 つのエディタ）、D7 の 2 案を試して決める、D4 の載せ替えを 1 手にできるか。data_contract の名詞を凍結（`EditorHistory`・`Document.confirmed` など）
- **P1**: Undo/Redo（2 つのエディタ・キー・Web 版のパネルのボタン。**フォーク元の改善のコミット**）→ Web 版で確かめる
- **P2**: デスクトップ — ツールバーの ↶ ↷（`useDesktopActions`）、載せ替えを 1 手に（D4）、`Document.confirmed` と「確定へ戻す」（Rust・`lib/desktop`）→ `tauri dev` で確かめる
- **P3**: 配布ビルドで利用者が確かめる

## スコープ外

- 履歴をファイルに残す（アプリを閉じても戻せる）・履歴の一覧から選んで戻す
- 確定を何世代も残す（D5 は最後の 1 つだけ）
- `history/`（`update_diagram` の 1 世代）を GUI から戻す
