# Spec: 輪のある図を取り込んだ時の段組み

**ID**: 18
**Date**: 2026-10-04
**Status**: Draft（rev0。査読と P0 の前）
**Branch**: 切らない（Phase 単位で main へ直接コミット）。spec 15〜17 と同じく、**フォーク元の改善と台帳はコミットを分け**、フォーク元のコミットだけで上流へ PR を出せる形にする
（フォーク元のコミットは `lib/desktop/` と台帳を含まない。PR を出すか・いつ出すかは利用者が決める, CLAUDE.md）

## Goal

spec 17 P0 で見つけた（候補 ⑤）: **全部のノードに入る線がある図（閉じた輪）は、取り込むと全部が 1 段に横並びになる**。
「受付 → 審査 → 通知 → 利用者へ戻る」で「利用者」が最初のノードの図はこの形になり、AI が段の流れを書くとふつうに出てくる。
1 段に並ぶと、段を結ぶ線が全部横に走り、戻る線は図の端から端へ渡る。

これを、**輪をほどいてから段を振る**ようにし、閉じた輪の図も段に分かれて並ぶようにする。Mermaid の描画（mermaid.js と merman）がどの段に置くかに、なるべく揃える。
変えるのは取り込み時の配置（と、それを使う枠の向きの並べ直し）だけで、保存済みの図の位置・保存・コード生成・`read_diagram` は変えない。

## 現況（2026-10-04、コードを読んで確かめた。描画の実測は P0）

- 取り込み時の段組みは 2 か所にあり、同じ数え方をしている:
  - 枠の無い図: `features/flowchart/flow-editor.tsx:556` の `layoutNodes`（フォーク元のもの。`handleImportMermaid` の中の関数）
  - 枠のある図: `features/flowchart/utils/nested-layout.ts:50` の `levelsOf`（spec 15 で `layoutNodes` と同じ数え方として写した）。`layoutNested` が入れ物（図・枠）ごとに、枠をまたぐ線を `liftTo` で持ち上げてから呼ぶ。
    spec 16 P5 の枠の向きの並べ直し（`frame-edit.ts` の `relayoutFrame`）も `layoutNested` を使う
- 数え方: **入る線の無いものを根にし、根から深さ優先で段を振る。一度訪れたものには二度と振らない**（`visited`）。根から届かないものは 0 段
  - **閉じた輪（根が無い）**: どこにも根が無いので、全部 0 段 = 1 段に並ぶ（spec 17 P0 の 1 で見た）
  - **輪の外に根がある図**（開始 → 利用者 → 受付 → … → 利用者）: 根からたどるので段に分かれる。戻る線は上へ戻る形になる（spec 17 P0 の格子はこの形にして測った）
  - **根から届かない輪が別にある図**: その輪は全部 0 段で、根と同じ段に並ぶ
  - **輪が無くても、段は「最初に着いた深さ」**: 一度訪れたものに振り直さないので、`A → B`・`A → C`・`C → B` で `A → B` が先に書いてあると、B と C が同じ 1 段になり、`C → B` が横に走る。
    名前の `Math.max(…)` は、訪れた時に 1 回しか呼ばれないので効いていない
- 同じ段の中の並びは、段を振った順（`Map` に入った順）。線の交差を減らす並べ替えは無い
- デスクトップで MCP の `open_in_editor` / `update_diagram` から届いた図も、同じ `handleImportMermaid` を通る（`lib/desktop/use-desktop-open.ts` の `onImport`）。Rust の側に配置は無い
- Mermaid の描画（mermaid.js 11.17.2 の `dagre-d3-es` 7.0.14、`src/dagre/acyclic.js` と `rank/index.js` を読んだ）:
  - **輪のほどき方（`dfsFAS`）**: ノードを**グラフに入った順**に深さ優先でたどり、たどっている途中の祖先へ戻る線を逆向きにする（逆向きの線は描く時に戻す）。
    設定 `acyclicer: "greedy"` の時だけ別の方法（`greedyFAS`）。mermaid の flowchart が何を渡しているかは確かめていない（P0 の 1）
  - **段の振り方**: 既定は network simplex（線の長さの合計を最小にする。全部の線は 1 段以上下へ）。ほかに `longest-path`・`tight-tree`。mermaid の flowchart の設定は確かめていない（P0 の 1）
  - グラフに入る順は、mermaid の flowDb の頂点の順（最初に出てきた順）の見込み。merman は dagre を Rust に写したもの（`dugong`）の見込みで、同じ結果になるかは P0 で測る

## 決めること

### D1. 輪のほどき方（**裁定 1**）

- **案 A（推奨）: dagre と同じ `dfsFAS`** — ノードを取り込んだ順（`ParsedMermaidData.nodes` の順 = Mermaid に最初に出てきた順。P0 で確かめる）に深さ優先でたどり、
  線は書いた順（`edges` の順）にたどる。たどっている途中の祖先へ戻る線を「戻る線」とし、段を振る時だけ逆向きに数える。線そのもの（向き・保存・描画）は変えない
  - 閉じた輪では、**最初に出てきたノードが一番上**になる（`利用者 → 受付 → 審査 → 通知 → 利用者` なら利用者が上、通知 → 利用者が戻る線）
  - Mermaid の描画と同じ線を戻る線にするので、エディタと描画で輪の切れ目が揃う見込み（P0 で確かめる）
- 案 B: 今の根からの深さ優先は残し、根から届かないものがあれば、その中で最初に出てきたものを根に足して続ける。輪の無い図・根から届く輪は今と同じ
- 案 C: 線の重みで戻る線を選ぶ（`greedyFAS`）。戻る線の本数は少なくなりやすいが、どれが戻る線になるかを人が読みにくい

### D2. 段の振り方（**裁定 2**）

輪をほどいた後（戻る線を逆向きにした、輪の無いグラフ）で段を振る。

- 案 A: **上からの最長路** — 入る線の無いものを 0 段、ほかは「入ってくる線の元の段 + 1」の最大。全部の線が 1 段以上下へ向く（同じ段の中を横に走る線が無くなる）。
  根（入る線の無いもの）は全部 0 段なので、深い所へ 1 本だけ入る根は、その相手から遠い上の段に置かれる
- 案 B（推奨）: **案 A の後に、根を下へ寄せる** — 出ていく線だけを持つものを、出ていく先の段 − 1 の最小まで下げる。
  network simplex（Mermaid）の結果に近いことが多い見込みで、計算は案 A と同じくらい軽い。P0 の 2 で Mermaid と突き合わせて決める
- 案 C: network simplex を自前で書く、または dagre（`@dagrejs/dagre`）を依存に足して段だけ使う — Mermaid と同じ段になるが、コードか依存が大きい
- 案 0: 今の数え方（最初に着いた深さ）を残し、D1 の輪のほどき方だけ直す — 輪の無い図の配置は一字一句変わらないが、現況の「横に走る線」は残る

推奨の理由: 輪をほどいても段の数え方が「最初に着いた深さ」のままだと、戻る線を逆向きにしたグラフでも横に走る線が残る（現況）。
最長路にすれば全部の線が上下に向き、spec 17 の回り道は「戻る線」と「段を飛ばす線」だけを相手にすればよくなる。案 A と B の違いは根の置き場所だけで、P0 で Mermaid に近い方を選ぶ

### D3. 置き場所

- 段の数え方を 1 つの純粋な関数にする（`nested-layout.ts` の `levelsOf` を作り直す。名前は変えるかもしれない）。輪のほどき方（D1）と段の振り方（D2）をその中に入れる
- `flow-editor.tsx` の `layoutNodes` の段の数え方を、その関数を呼ぶ形にする（フォーク元の重複を 1 つにする）。同じ段の中の並び・位置の計算（`placeByDirection`）は変えない
- `layoutNested` は今のまま `levelsOf` を呼ぶ（枠をまたぐ線は `liftTo` で持ち上げた後の線で数える）。`relayoutFrame` も同じ関数を通る

### D4. 変わるもの・変えないもの

- 変わる: 取り込み時の配置（Web 版のインポート、デスクトップの MCP の `open_in_editor` / `update_diagram` で位置の無い図・ノード、ツールバーのインポート）と、枠の向きを見出しで変えた時の並べ直し（spec 16 P5）
- 変えない: 保存済みの図の位置（`Document.layout` を当てる）・生成器・保存・`read_diagram`・Rust。同じ段の中の並び（交差を減らす並べ替えはしない）
- 裁定 2 が案 A・B・C なら、**輪の無い図でも配置が変わる場合がある**（現況の「最初に着いた深さ」で横に走っていた線がある図）。初期図・テストの期待で変わるものを P0 の 3 で数える

     線を書く順だけを変えたもの / 枠の中の輪 / 枠をまたぐ輪（受付 → 審査 → 通知 → 利用者）/ `TD` と `LR` / 現況の「横に走る線」（`A → B`・`A → C`・`C → B`）/ 深い所へ 1 本だけ入る根。

## 受け入れ条件

1. 閉じた輪の図（枠あり・なし、`TD`・`LR`）を取り込むと、段に分かれて並ぶ（1 段に並ばない）。輪のどこが上になるかは D1 の規則どおり
2. P0 の 2 の格子で、ノードの段の順が Mermaid の描画（mermaid.js）と揃う。揃わないものは spec に理由を書いて残す
3. 輪の無い図の配置は、裁定 2 の規則どおり（案 0 なら一字一句変わらない。案 A・B・C なら変わる図を P0 の 3 で数えた範囲に収まる）
4. 保存済みの図を開き直した位置は変わらない。保存・コード生成・`read_diagram` の出力は変わらない
5. Web 版（GitHub Pages）のフローチャートのエディタで 1・2 ができる（デスクトップ専用の変更を含まない）

## スコープ外

- 同じ段の中の並べ替え（線の交差を減らす。Mermaid の `order`）
- 段の中の位置の詰め方（Mermaid の `position`。今の中央揃えのまま）
- 保存済みの図を並べ直す操作（図全体の「並べ直し」ボタンなど）
- 戻る線の描き方（spec 17 の回り道のまま）
- ER 図の配置
