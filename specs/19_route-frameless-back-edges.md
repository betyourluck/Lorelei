# Spec: 枠の無い図でも、ノードを貫く線を外へ回す

**ID**: 19
**Date**: 2026-10-04
**Status**: Draft（rev0。査読と P0 の前）
**Branch**: 切らない（Phase 単位で main へ直接コミット）。spec 15〜18 と同じく、**フォーク元の改善と台帳はコミットを分け**、フォーク元のコミットだけで上流へ PR を出せる形にする
（フォーク元のコミットは `lib/desktop/` と台帳を含まない。PR を出すか・いつ出すかは利用者が決める, CLAUDE.md）

## Goal

spec 18 P2 で見つけた（候補 ⑧）: **枠の無い図の戻る線が見えず、ラベルのボタンが押せない**。

- LR の閉じた輪 `計画 → 実行 → 評価 → 改善 → 計画` の 改善 → 計画 は、曲線が y 一定の直線になって 4 つのノードを真横に貫き、ノードの後ろに隠れる。
  曲線の中点が 実行 → 評価 の線の中点とほぼ同じ所で、2 つのボタンが重なって 1 つしか見えない（利用者の言「改善から計画に戻るときに回り込みは発生していない」）
- 枠の無い閉じた輪の「完了」（入金確認 → 注文受付）は、曲線の中点が発送と取り寄せの隙間に当たり、ボタンがノードの後ろに隠れた

spec 17 の裁定 1 で、両端とも図の直下の線は「同じ高さのノードの後ろに隠れるだけ」なので回さないと決めた。spec 18 で閉じた輪が段に分かれ、枠の無い図にも戻る線がふつうに出るようになり、
隠れた線と押せないボタンが目立つようになった。これを、**枠の無い図でも、ノードを貫く線（またはボタンがノードに重なる線）は spec 17 の回り道で外へ回す**ようにする。

変えるのはエディタの線の描き方（表示）だけで、保存・コード生成・`read_diagram`・書き出しには何も足さない・変えない（spec 17 と同じ）。

## 現況（2026-10-04、コードを読んで確かめた。画面の測りは P0）

- 回すかの判定は `features/flowchart/utils/edge-route.ts` の `needsRoute`（spec 17 裁定 1 = 案 A）: 今の曲線、または曲線の中点のボタンが、
  **どちらの端も中にいない枠**・**線の高さより低いノード**・**端である枠の内側**のどれかと交わる線だけを回す。
  線の高さ = 端のうち親を持つものの高さの大きい方（xyflow の `getElevatedEdgeZIndex`）なので、**両端とも図の直下の線（高さ 0）は、ノード（高さ 0）と交わっても回さない**
- spec 17 P0 の 4: 線の高さ = ノードの高さの時は、ノードが線の上に描かれて線を隠す。ボタン（`EdgeLabelRenderer`）もノードより下の層に描かれる（failures #25。枠のある図では spec 17 で線のラベルを枠より上に上げたが、ノードより下のまま）
- 回した線どうしのボタンは重ならないように置く（spec 17 D3）が、**回さない線のボタンどうしの重なり**は見ない（互いに逆向きの組だけ `adjustEdgeLabelPosition` でずらす）
- spec 17 の裁定 1 の案 B（枠とノードの両方を回す対象にする）は「Web 版の枠の無い図の見た目が変わる。ノードの後ろに隠れているだけの線まで回す」として採らなかった。
  その時は、枠の無い図の戻る線は「輪の外に根がある図」でしか段に分かれず（閉じた輪は 1 段に並んでいた）、目立たなかった

## 決めること

### D1. どの線を回すか（**裁定 1**。spec 17 の裁定 1 を改める）

- **案 A（推奨）: 枠と、全部のノード** — 今の曲線か中点のボタンが、どちらの端も中にいない枠・**ノード（高さを問わない）**・端である枠の内側と交わる線を回す（spec 17 の案 B）。
  枠の無い図の戻る線・段を飛ばす線（`A → B → C` と `A → C`）も回る。回さない線の形は今のまま
- 案 B: 戻る線だけ — 案 A の対象のうち、**上へ戻る線**（入口が出口より流れの手前の段にある線。spec 18 の戻る線）だけを足す。段を飛ばす順向きの線は、ノードの後ろに隠れたまま
- 案 C: ボタンだけ — 中点のボタンがノード・ほかの線のボタンと重なる線だけを足す。線そのものはノードの後ろに隠れたままのことがある

推奨の理由: 隠れる線は戻る線だけでなく、段を飛ばす線も同じ（ノードの後ろを通るので、どこへつながっているか読めない）。spec 17 の回り道は図全体で 1 回に計算し、回した線どうしの重なりとボタンも離すので、対象を広げても形は崩れない。
Web 版の枠の無い図の見た目は「ノードを貫く線がある図」だけ変わる（P0 で数える）

### D2. 回さない線のボタンどうしの重なり

- 案 A（推奨）: 扱わない（スコープ外、候補 ⑦ のまま）。D1 の案 A なら、LR の閉じた輪の重なりは戻る線が回ることで消える
- 案 B: 回さない線のボタンも、spec 17 D3 のボタンの置き方（重ならない所へずらす）に入れる

### D3. 速さ

- 回す線が増える（枠の無い図の戻る線・飛ばす線）。spec 17 P1 の測り（ノード 110・線 150 の図で回す線 58 本、全部の計算 36ms、ドラッグ中 22ms、重い時は間引く）に足して、回す線が何本・何 ms 増えるかを P0 で測る

## 受け入れ条件

1. 枠の無い図で、ノードを貫く線（裁定 1 の対象）は外へ回り、線もボタンもノード・枠を横切らない（spec 17 の受け入れ条件 1・2 と同じ確かめ）
2. LR の閉じた輪で、戻る線が見え、そのボタンがほかのボタンと重ならず押せる
3. 回す対象に当たらない線の形は変わらない
4. ノード 110・線 150 の図のドラッグが、spec 17 の間引きの形で付いてくる（P0 の 3 の測りで遅くなりすぎない）
5. 保存・コード生成・`read_diagram` の出力は変わらない
6. Web 版（GitHub Pages）のフローチャートのエディタで 1〜3 ができる（デスクトップ専用の変更を含まない）

## スコープ外

- 回さない線のボタンどうしの重なり（D2 の案 A なら。候補 ⑦）
- 回した線の通り道を手で動かすこと（候補 ⑥）
- 段組み（spec 18 のまま）・段の中の並べ替え
- ER 図の線
