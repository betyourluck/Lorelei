# Spec: 左ペインの幅を変えられるようにし、図を開く時に初期図を見せない

**ID**: 05
**Date**: 2026-09-26
**Status**: In Progress（rev1 承認 2026-09-26。rev0 に D3・D4 の見せ方の利用者裁定を反映。P1 着地、次は P2）
**Branch**: なし（Phase 単位で main へ直接コミット）

## Goal

利用者の要望（2026-09-26）:

> 左ペインにスライダーをつけて横幅を可変にする
> 初期図がちらっと見える件をやりましょう

1. 図の一覧（左ペイン）とエディタの間につまみを置き、ドラッグで幅を変えられるようにする
2. 図を開いた時に、エディタの初期図（`startNode[Start]` / `ユーザー` テーブル）や、位置を当てる前の図が一瞬見えるのをなくす（spec 04 P0 の「残した課題」）

どちらもデスクトップ版だけのもの（`lib/desktop/`）。Web 版には出さない。

## 現況（2026-09-26）

### 1. 左ペインの幅は固定

- `lib/desktop/document-list.tsx` の `DOCUMENT_LIST_WIDTH = "240px"`。開閉（タイトルバーの ≡）は `desktop-shell.tsx` の `useState(true)` で、起動し直すと開いた状態に戻る
- 分割のライブラリは入っていない

### 2. 前例: Fuseforks の `PaneSplitter.vue` / `usePaneLayout.ts`（2026-09-26 に読んだ）

- つまみは `role="separator"`・`aria-orientation`。ポインタを押すと `setPointerCapture`（素早く動かしてつまみの外へ出ても追従）
- 移動量は**差分**で渡し、原点をその都度更新する（開始位置からの差で計算すると、上限に張り付いた後に戻す時に空走りが出る）
- 当たり判定を見た目の線より広げる（1〜2px の線は掴めず、隣のペインを押してしまう）
- ダブルクリックで既定の幅へ戻す（ドラッグで見失った時の避難路）。矢印キーで 16px ずつ
- 寸法は上限・下限に収める（左ペインは 220〜620px）。保存先は localStorage（理由: 表示の都合で、アプリの状態ではない。壊れていたら既定値へ落とす）
- Kataribe も右ペインで同じ形（`window` に `pointermove` / `pointerup` を張り、ドラッグ中は `user-select: none` とカーソルを固定）

### 3. 図を開く時の見え方の順番（`use-doc-session.ts` / `use-desktop-open.ts`）

1. `open()` が図を読み、変換を預け（`queueOpen`）、`generation` を進める → `Fragment key` でエディタを作り直す。**この時点のエディタはフォーク元の初期図**
2. エディタの取り込み（`useDesktopOpen` の `drain`）が預けた図を取り込む（`await takePendingOpen()` の後なので、最低 1 回は描画を挟む）→ ノードは自動の配置
3. `onNodesChanged` が「取り込み済み・キーがそろった」を見て、保存してあった位置を当てる（`withLayout`）→ ノードが跳ぶ
4. その後の変化から自動保存（準備済み）

- 利用者が見ているのは 1〜3 の間（「最初に初期化のノードがちらっと出てから変わる」, 2026-09-25）
- 図の一覧は「準備済み」を `readyRef` で既に知っている。ただし ref なので、画面の出し分けには使えていない
- 準備済みにならない図がある: 変換できない図（`unopenable`。今は初期図のまま「開けないので保存しません」を出す）、新規作成の直後（エディタが作り直された時点で準備済み = `editorMounted`）

## 決めること

### D1. つまみ（`lib/desktop/pane-splitter.tsx`）

Fuseforks の `PaneSplitter` を React に移す。見た目は図の一覧の右の境界線（今の `borderRightWidth="1px"`）をつまみにする。

- ドラッグ: `pointerdown` で `setPointerCapture`、`pointermove` で差分を渡す、`pointerup` / `pointercancel` で終わる。ドラッグ中は `user-select: none` とカーソル `col-resize`
- 当たり判定は線の左右に 4〜6px 広げる。ホバーとドラッグ中は線を強調する
- ダブルクリックで既定の幅へ戻す。矢印キー（左右）で 16px ずつ（`tabIndex=0`、`role="separator"`、`aria-orientation="vertical"`、`aria-valuenow/min/max`）
- 図の一覧を閉じている間（≡）はつまみも出さない

### D2. 幅の範囲と既定（案）

| 値 | 案 | 理由 |
|---|---|---|
| 既定 | 240px（今と同じ） | 変えない |
| 下限 | 180px | 「新規作成」ボタンと、題名が数文字見える幅 |
| 上限 | 480px、かつ窓の幅の半分まで | エディタが狭くなりすぎない |

### D3. 幅と開閉を覚える場所（利用者裁定 2026-09-26: localStorage。開閉も一緒に覚える）

- **localStorage**（Fuseforks と同じ理由 — 表示の都合で、図の一覧やアプリの状態ではない）。キーは `lorelei.layout.v1`、中身は `{ listWidth, listOpen }`。
  読めない・壊れている・範囲外は既定値か範囲の端へ落とす（画面が開けなくなるより良い）。書けなくても操作は続ける
- 採らなかった案: Rust の `state.json`（JS からファイルに触らない方針 = spec 01 D8 には沿うが、表示の都合のために command とイベントが増える）/ 覚えない
- localStorage は WebView の起点ごと（dev の `http://localhost:3000` と配布版は別）。dev で変えた幅は配布版に引き継がれない — 困らない
- 開閉（≡）も覚える。閉じて終了したら、次も閉じたまま起動する

### D4. 図を開く間はエディタを隠す

図の一覧が「開き終えた」と言うまで、エディタの領域を**隠す**（`visibility: hidden`。`display: none` にしない — ReactFlow がノードの大きさを測れなくなり、取り込みと位置の当て込みが進まない）。

- `useDocSession` に `settled: boolean`（画面の出し分けに使う state）を足す。`open()` と届いた図（`beforeImport`）で `false`、次のどれかで `true`:
  1. 準備済みになり、位置を当てる必要が無い（`onNodesChanged` が `save: true` を返した回）
  2. 位置を当てた後の最初の変化（当てた位置が反映された回）
  3. 新規作成の直後（`editorMounted`）
  4. 変換できない図（`unopenable`。初期図が見えるが「開けないので保存しません」を出しているので隠さない）
  5. **時間切れ**（案 1.5 秒）— 門が何かの理由で開かなくても、画面が空のまま止まらないように
- 隠している間は、エディタの領域の真ん中に小さく「読み込み中…」を出す。0.2 秒以上かかった時だけ出して、普段の速い切り替えでは点滅させない（利用者裁定 2026-09-26）
- ツールバーの操作（ノード追加・コード生成など）は、隠している間は押せないようにする（見えない図に足さない）

## Phase

- **P1**: つまみ（D1〜D3）。テスト: 幅の収め方（下限・上限・窓の半分）と保存値の読み直し（壊れた値・範囲外）を純粋関数で、つまみのドラッグ・ダブルクリック・矢印キーを vitest で
- **P2**: 隠す（D4）。テスト: `settled` の移り変わり（開く → 取り込み → 位置を当てる → 見える / 新規作成 / 変換できない / 時間切れ）を vitest で
- **P3**: 実機 — 配布ビルドで、幅をドラッグ・ダブルクリック・起動し直して覚えているか、AI の図・保存した図・新規作成・種類の切り替えで初期図が見えないか

## P1 結果（2026-09-26）

- 着地: `lib/desktop/pane-splitter.tsx`（つまみ。Fuseforks の `PaneSplitter.vue` を React に移した）、`lib/desktop/pane-layout.ts`（`clampListWidth`・`loadLayout` / `saveLayout`・`usePaneLayout`）。
  `desktop-shell.tsx` は開閉を `usePaneLayout` に移し、一覧の右につまみを置いた（一覧の右の境界線はつまみが兼ねる）。`document-list.tsx` は幅を受け取る（`DOCUMENT_LIST_WIDTH` を撤去）
- 幅の足し方は「見えている幅（窓の半分で収めた値）+ 差分」。保存値のままに足すと、窓の半分に張り付いた後で戻す時に空走りが出る
- data_contract に `DesktopLayout` を先に凍結（localStorage `lorelei.layout.v1`、`listWidth` / `listOpen`、読めない時の扱い）
- テスト（Red → Green）: `pane-layout.test.ts` 6 件（既定・範囲・窓の半分・読み直し・壊れた値と範囲外・読み書きできない localStorage）、
  `pane-splitter.test.tsx` 4 件（aria・差分のドラッグ・押していない時の移動は無視・ダブルクリックと矢印キー）、`document-list.test.tsx` 2 件（ドラッグで幅が変わり幅と開閉を覚える・起動時に覚えた値で始まる）。
  jsdom は `PointerEvent` を持たないので、テストの横に最小のもの（`pointer-event.ts`）を置いた（フォーク元の `setup.ts` は触らない）
- デスクトップの vitest 67 件緑、型検査・lint 通過
- **実機（`tauri dev`）で利用者が確認**: ホバーで線とカーソルが変わる / ドラッグで幅が変わり素早くても追従し、下限・上限で止まる / ダブルクリックで戻る /
  最大の幅にして閉じて終了すると、閉じたまま起動し、開くと最大の幅のまま

## 受け入れ条件

1. つまみをドラッグすると図の一覧の幅が変わり、下限・上限（窓の半分）を越えない。素早く動かしても追従する
2. ダブルクリックで 240px に戻る。矢印キーでも動く
3. 起動し直しても幅と開閉を覚えている。保存値が壊れていても起動できる
4. 保存した図・AI から届いた図・インポートした図・種類の切り替えのどれで開いても、エディタの初期図と、位置を当てる前の図が見えない
5. 新規作成・変換できない図・時間切れの時は、隠したまま止まらない
6. Web 版（GitHub Pages）の見た目と動きは変わらない

## スコープ外

- 右側のパネル（フォーク元のパネルはデスクトップでは隠している）の幅
- 図の一覧の開閉のアニメーション
- 開いた後の表示位置（ビューポート）の合わせ込み（見えるようになった時に図が画面の外にある、などが見つかったら別に扱う）
