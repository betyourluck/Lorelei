# Spec: ER 図のテーブルを消せるようにし、テーブルとノードの削除に確認を入れる

**ID**: 06
**Date**: 2026-09-26
**Status**: In Progress（rev1 承認 2026-09-26。rev0 に査読 2 件を反映。P1 から）
**Branch**: なし（Phase 単位で main へ直接コミット）

## Goal

利用者の指摘（2026-09-26、spec 05 P3 の実機で）:

> ER図でテーブルが消せない。これは mermaid-editor の機能不全だと思う。ちなみにノードは消せる。

利用者裁定（2026-09-26）: 削除はテーブルの見出しにボタンを置く。**消す前に確認を入れる。フローチャートのノードにも確認を入れる**。

**フォーク元の改善**（Web 版にもある抜け）なので、デスクトップの変更とはコミットを分け、上流へ PR で返せる形にする（掟）。`lib/desktop/` には触らない。

## 現況（2026-09-26）

- **ER 図のテーブル**（`features/er-diagram/components/node/er-table-node.tsx` / `er-table-content.tsx`）: 削除の処理が無い。持っているのは名前とカラムの変更（`onNameChange` / `onColumnsChange`）だけ。
  見出しは「テーブル名」の入力欄と「カラム追加」ボタン。カラムは行ごとの × で消せる（確認なし）
- **フローチャートのノード**（`features/flowchart/components/node/node-menu.tsx`）: 右上の「⋮⋮」メニューに「削除」。確認なしで消える（`flow-editor.tsx` の `handleNodeDelete` がノードとつながる辺を消す）
- **キーボード**: xyflow（12.8.2）の既定で、選んだノード・辺は Backspace で消える（`deleteKeyCode` の既定）。どちらのエディタも設定していない。
  ER 図のテーブルは中が入力欄だらけで、クリックすると入力欄に入るので実際には選びにくいが、枠を押せば選べる。確認は無い
- xyflow 12 には `onBeforeDelete`（消す前に呼ばれ、`false` を返すと消さない。Promise を返せる）がある。**Backspace も `useReactFlow().deleteElements` もこれを通る**
  （`@xyflow/react` の `deleteElements` → `@xyflow/system` の `getElementsToRemove`。消すノードに**つながる辺も自動で含める**）。`setNodes` で直接消すと通らない
- 入力欄（input / textarea）に焦点がある時の Backspace は、xyflow が削除の合図にしない（`useKeyPress` の `isInputDOMNode`）。文字を消すだけ
- 確認の部品: Yamada UI の `Dialog`（見出し・本文・`cancel` / `success` のボタン、`onCancel` / `onSuccess`）。フォーク元は `Modal` を使っている（インポート・ダウンロード）
- エディタに「元に戻す」は無い。消したら戻せない

## 決めること

### D0. 削除の経路は 1 本（査読 1-2・2-(1) を受けて足した）

ボタン（D1・D2）もキーボード（Backspace）も **`deleteElements` → `onBeforeDelete` → 確認** の 1 本を通す。

- ボタンは `useReactFlow().deleteElements({ nodes: [{ id }] })` を呼ぶだけ。確認は `onBeforeDelete` の 1 か所で出す（ボタンの側で確認してから消すと、経路が 2 本になり、二重の確認や確認の抜けが起きうる）
- つながる辺は xyflow が一緒に消す。ER 図の側に「辺を一緒に消す」処理を書かなくてよい。フローの `handleNodeDelete`（`setNodes` / `setEdges` で直接消す）はこの経路に置き換える
- 確認は Promise で返す: `useConfirmDelete()` が `confirm(target) => Promise<boolean>` と、エディタに 1 つだけ置く `<ConfirmDeleteDialog>` を返す。`onBeforeDelete` はそれを await する

### D1. ER 図のテーブルの見出しに削除ボタン（利用者裁定 2026-09-26）

- 「カラム追加」の隣にごみ箱のアイコンボタン（`aria-label`「テーブル『{名前}』を削除」、名前が空なら「このテーブルを削除」。`title`「テーブルを削除」）
- 押すと D0 の経路で確認 →「削除」でテーブルと、**つながっているリレーション（辺）も一緒に**消える
- `ERTableNodeProps` に `onDelete?: () => void` を**任意で**足す（`createNewERTableNode` などの既存の型・テストを壊さない）。`er-diagram-editor.tsx` がノードごとに渡す（`onNameChange` などと同じ渡し方）
- ボタンの `onClick` / `onPointerDown` は伝播を止める（ノードの選択・ドラッグと干渉させない）

### D2. フローチャートのノードの「削除」に確認（利用者裁定 2026-09-26）

- 「⋮⋮」メニューの「削除」を押すと D0 の経路で確認 →「削除」でノードとつながる辺が消える

### D3. 確認のダイアログ（共通）

Yamada UI の `Dialog` で 1 つ作り、両方で使う（`components/` に置く。フォーク元の共通部品の置き場）。**ダイアログはエディタ（`flow-editor.tsx` / `er-diagram-editor.tsx`）の直下に 1 つだけ置く** —
ノードの中に置くと、ノードの数だけでき、消した瞬間にダイアログごと消える（査読 2-(3)）。

見出しの件数は**消すノード（テーブル）の数だけ**を数える（巻き添えで消える辺は数えない）:

| 場合 | 見出し |
|---|---|
| 1 つ・名前あり | 「『{名前}』を削除しますか？」（ER 図はテーブル名、フローはラベル） |
| 1 つ・名前なし | 「このテーブルを削除しますか？」/「このノードを削除しますか？」 |
| 2 つ以上 | 「選択した {n} 個のテーブルを削除しますか？」/「選択した {n} 個のノードを削除しますか？」 |

- 本文（共通）: 「つながっている線も一緒に消えます。元に戻せません。」
- ボタン: 「やめる」（既定の焦点）/「削除」（危険の色）。Esc・枠の外を押すと「やめる」と同じ

### D4. キーボードの削除（Backspace）も同じ確認を通す

ボタンで確認を入れても、Backspace では確認なしで消えるのでは片手落ち。D0 の `onBeforeDelete` が、**ノード（テーブル）を含む削除**なら確認を出し、「削除」の時だけ消す。

- 辺だけの削除（線の × や、線を選んで Backspace）は今どおり確認なし（利用者の指摘はテーブルとノード）。判定は `nodes.length > 0` の純粋関数にしてテストで固める
- 入力欄の編集中の Backspace は xyflow の既定どおり文字を消すだけで、確認は出ない（`deleteKeyCode` は変えない）

## Phase

- **P1**: D0〜D4。テスト（Red → Green）: 見出しの文言と件数・確認の要否（ノードを含むか）を純粋関数で / `useConfirmDelete` の「削除」で true・「やめる」と Esc で false /
  ER 図の見出しのボタン → 確認 →「削除」でテーブルとつながる辺が消える・「やめる」で消えない / フローのメニューの「削除」→ 同じ / 辺だけの削除では確認が出ない /
  入力欄での Backspace で確認が出ない。フォーク元のテスト（`__tests__/features/`）の書き方に合わせる
- **コミットの分け方**（上流へ PR で返せる形, 査読 1-6）: main へ直接、フォーク元の改善だけのコミットを 3 つ — (a) D3 の確認の部品と `useConfirmDelete` /
  (b) D1 の ER 図のテーブル削除 / (c) D2・D4 のフローのノードの確認と Backspace。`lib/desktop/` や spec・台帳の変更は別のコミットにする
- **P2**: 実機 — dev でテーブル・ノードの削除（ボタン・Backspace）、確認の「やめる」、消した後の自動保存と「コード生成」。Web 版（`next dev` のブラウザ）でも同じく動くか

## 受け入れ条件

1. ER 図のテーブルを見出しのボタンから消せる。つながっていたリレーションも消える
2. テーブル・フローのノードとも、消す前に確認が出る。「やめる」・Esc では消えない
3. Backspace でテーブル・ノードを消す時も確認が出る。辺だけなら今どおり確認なしで消える
4. 消した後の図がデスクトップ版の自動保存に乗り、「コード生成」の Mermaid からも消えている
5. Web 版でも同じく動く（フォーク元の改善）。フォーク元の既存テストで落ちるものが変更前と同じ顔ぶれ（failures #3 = この環境では変更と無関係に時間切れで落ちるものがある。2026-09-26 時点では ArrowTypeSelector の 1 件）
6. テーブル名・カラム名・ラベルの入力欄で Backspace を押しても、文字が消えるだけで確認は出ない

## スコープ外

- 元に戻す（Undo）
- カラムの削除（行の ×）・辺の削除への確認
- 上流への PR を出すこと自体（出すかは利用者が決める。出せる形にしておくまで）
