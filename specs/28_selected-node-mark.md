## Goal

利用者の言（2026-10-29）: 「Shift キーを押したまま node クリックで複数選択できるようにして欲しい。複数選択したノードはまとめて移動できるようにする。これはよく GUI である操作なのでわかると思う」

フローチャートと ER 図のキャンバスで、Shift+クリックでノード（テーブル・枠）を選びに足し、選んだものをまとめてドラッグで動かせるようにする。Web 版とデスクトップで同じ。

続く利用者の言（同じ日、下調べの途中で）: 「ごめん、Ctrl があったんだね」 — 現況のとおり、Ctrl+クリックでの複数選択とまとめての移動は今もある。
気付きにくいのは、**選んだノードに印が出ない**ため（現況）。Shift を足すか（D1）と、選んだ印を入れるか（D3）を分けて裁定する

## 裁定（2026-10-29、利用者）

利用者の言: 「Ctrl があったんだね。問題は選択されたと気づきにくいのだけだね。Shift ではなくて Ctrl のままでよい。ただ選択されたとユーザーがわかりやすくしてくれ」

- **D1: Shift は足さない**（`multiSelectionKeyCode` は xyflow の既定 = Ctrl・Mac は ⌘ のまま）
- **D2・D4: 今のまま**（範囲選択・まとめての移動は今ある）
- **D3: 選んだ印を入れる** — 推奨の形（外側に 2px 空けて 3px の輪、色の名 `selectionRing`）。対象はフローチャートのノード・ER 図のテーブル・枠（枠は今の濃い縁に足す。P1 で画面を見る）
- 受け入れ条件・Phase を下のとおり改めた（rev1）

## 現況（2026-10-29、xyflow のソースを読み、Web 版を裏の Edge で試した）

試した道具: scratchpad の `spec28-p0/select-probe.mjs`（`web-dev` に Playwright の Edge でつなぎ、図を取り込んで修飾キー付きのクリックとドラッグをする）。

- **xyflow 12.8.2 の既定**（`@xyflow/react` の `ReactFlow` の引数の既定値）: 複数選択のキー `multiSelectionKeyCode` は **Windows・Linux は Control、Mac は Meta（⌘）**。
  範囲選択のキー `selectionKeyCode` は **Shift**（Shift を押したまま何も無い所からドラッグすると矩形で囲んで選ぶ）。2 つのエディタの `<ReactFlow>` はどちらも渡していない（既定のまま）
- **今の振る舞い**（Web 版で試した）:
  - **Ctrl+クリックで選びに足せる**（選んでいるノードをもう一度 Ctrl+クリックすると外れる）。フローチャート・ER 図とも
  - **Shift+クリックは、そのノード 1 つだけを選び直す**（Shift は複数選択のキーではないので、xyflow はふつうのクリックとして扱う。範囲選択はドラッグが何も無い所から始まった時だけで、ノードの上では始まらない）
  - **複数を選んで、その 1 つをドラッグすると全部が同じだけ動く**（フローチャートで 2 つ、ER 図で 2 つ。xyflow の XYDrag が選んでいるノードをまとめて動かす。枠とその中のノードを両方選んでも中が二重に動かないよう、親が選ばれている子は外す）
  - Shift+ドラッグの範囲選択は働く（囲んだノードを選ぶ。前の選択は消える）。Shift+クリック・Shift+ドラッグで文字が選択される（青くなる）ことは、ノードの上・キャンバスの上では起きなかった（パネルの上から Shift+ドラッグを始めた時だけ、パネルの文字が選択された）
  - **選んだノードが見分けられない**: フローチャートのノード（`editable-node.tsx`）と ER 図のテーブル（`er-table-node.tsx`）は `selected` を見た目に使っておらず、選んでも枠・影・輪郭が選んでいないノードと同じ（計算されたスタイルで確かめた）。
    選んだ時に見た目が変わるのは枠（`subgraph-node.tsx`: 縁が濃い 2px になり、大きさのつまみが出る）だけ
- **アプリ側はすでに複数に対応している**: フローチャートの `onNodeDragStart` / `onNodeDragStop`（`flow-editor.tsx:485-520`）は動かした全部のノード（xyflow の `dragged: Node[]`）を受け、
  手を離した時に中心を含む枠へ付け替える処理（spec 15 D5）も全部に当てる。やめた時に戻すのも全部。削除（Backspace）も選んでいる全部を確認してから消す（spec 06・15）。
  手を離した時の線の全部の探し直し（spec 17・22）は、`dragging` の付いたノードの数に依らない
- **Shift はほかに使っていない**: 範囲選択（xyflow）以外に、Shift を見ている所はフォーク元・`lib/desktop` に無い（grep）

## 決めること

### D1. 選びに足すキー

- **案 A（推奨）: Shift を足し、今の Ctrl（Mac は ⌘）も残す** — `multiSelectionKeyCode` に `["Shift", Ctrl か ⌘]` を渡す。
  **Shift+クリックは、選んでいないノードなら足し、選んでいるノードなら外す**（xyflow の複数選択のキーの振る舞いそのまま。PowerPoint・Figma などと同じ）。何も押さないクリックは今どおり、そのノード 1 つを選び直す
- 案 B: Shift だけにする（Ctrl+クリックを外す） — 今の振る舞いを減らすことになる。採らない

### D2. 範囲選択（Shift+ドラッグ）

- **推奨: 今のまま**（何も無い所から Shift+ドラッグで囲む。始めた時に前の選択は消える）。Shift を複数選択のキーにしても、範囲選択はキャンバスの何も無い所から始めた時だけなので、ノードの Shift+クリックとはぶつからない
- 「囲んだものを今の選択に足す」は xyflow の範囲選択が始めに選択を消すので、変えるには xyflow の外で持つことになる。今回は入れない（スコープ外）

### D3. 選んだ印

- **推奨: 選んだノードとテーブルの外側に、2px 空けて 3px の青い輪を出す**（枠は今の「縁が濃くなる」を残し、同じ輪も足すかは P1 で画面を見て決める）。
  色は新しい色の名 `selectionRing`（`[blue.500, blue.400]`、spec 27 の `components/providers/theme.ts`）。キャンバスの地に対して ライト 3.38・dark 6.70（文字でない部品の 3:1 を超える）。
  選んでいないノードの見た目は今と同じ（spec 27 の台本でライトの計算されたスタイルが前と一致することを確かめる）
- 印が無いと、複数を選んでも何が選ばれているか分からない（現況）ので、D1 と一緒に入れる

### D4. まとめての移動

- **推奨: 追加の処理は入れない**（xyflow と今のアプリが対応している。現況）。P1 で、選んだ複数を枠へ落とす・枠から出す・付け替えで線が消える時の確認とやめる（全部が戻る）・枠と外のノードを一緒に動かす を Web 版で確かめる

### D5. 範囲

- 2 つのエディタ（フローチャート・ER 図）。Web 版とデスクトップで同じ（キャンバスはフォーク元の部品なので、デスクトップの差し込みは要らない）
- 線の選択（線を Shift+クリックで足す）: xyflow は線にも同じ複数選択のキーを使うので、Shift で線も足せるようになる。線は図ごとに数が多く選んで何かする操作も無いので、印は今の xyflow のまま（何もしない）

## 受け入れ条件（rev1）

1. 2 つのエディタで、選んだノード・テーブル・枠に輪が出る（クリック・Ctrl+クリックで足したもの・範囲選択で囲んだもの。ライトと dark）。選びから外すと消える
2. 選んでいないものの見た目は前と同じ（spec 27 の台本で、ライトの計算されたスタイルが前の記録と一致）
3. 輪はキャンバスの地に対して 3:1 以上（ライト・dark）
4. 操作は今と同じ（クリック・Ctrl（⌘）+クリック・範囲選択・まとめての移動・枠へのドロップ）
5. テスト（vitest）: 選ぶと輪が出て、外すと消える（2 つのエディタと枠）。要の分岐を壊して落ちる
6. 配布ビルドで利用者が確かめる
