# Spec: 回さない線どうしのボタンの重なりを解く

**ID**: 21
**Date**: 2026-10-09
**Status**: Draft（rev2。P0 着地、D1〜D6・D3-1・D3-2 を裁定（2026-10-09）。次は P1）
**Branch**: 切らない（Phase 単位で main へ直接コミット）。spec 15〜19 と同じく、**フォーク元の改善と台帳はコミットを分け**、フォーク元のコミットだけで上流へ PR を出せる形にする
（フォーク元のコミットは `lib/desktop/` と台帳を含まない。PR を出すか・いつ出すかは利用者が決める, CLAUDE.md）

## Goal

spec 17・19 で残した候補 ⑦: **回さない線（今の曲線のままの線）どうしで、ラベルのボタンが重なる**。

- spec 17 P2 の画面: 枠のある図で、至急と再申請が曲線に戻った位置で 2 本のボタンが重なった
- spec 19 P1 の画面: 枠の無い大きな図（ノード 100・線 150）で、ボタンどうしの重なりが 11 組残った（どれも回さない線どうし）

ボタンはラベルだけでなく、**矢印の種類の切り替えと線の削除（×）を持つ**（`EdgeContent`）。重なると、下のボタンのラベルが読めないだけでなく、
押したつもりの線と違う線の矢印を変える・違う線を消すことが起きうる。

これを、**回さない線のボタンが重なる時は、重ならない所へずらす**ようにする。ずらしたボタンも、どの線のボタンかが分かる位置に置く。

変えるのはエディタの線のラベルの置き方（表示）だけ。**保存ファイル・コード生成・`read_diagram`・書き出しの出力**には何も足さない・変えない（spec 17・19 と同じ）。

## 裁定（2026-10-09、利用者。P0 の後）

- **D1: 案 A** — 自分の曲線の上で滑らせる（s = −8, +8, −16, +16, … で中点に近い順、同じ近さは出口の側が先。置けなければ直交する向きに 2px 刻み。それでも置けなければ今の位置に残し、解けない組として数える）。
  ボタンの中を自分の線が通るので、どの線のボタンかが分かる。線の形は変えない
- **D2: 逐次に置く手順**（rev1 のまま）— 今重なっていない線は動かない（受け入れ条件 3）
- **D3: 案 A** — きっかけはボタンどうしの重なりだけ。置き場の障害は、taken から自分を除いた全部のボタン・全部のノード（端を含む）・枠の見出しの帯。回した線の折れ線と枠の本体は障害にしない
  - **D3-1: 入れない** — ノードに少しかかるだけの線は動かさない（対象は 5 図で 1 本ずつ。受け入れ条件 3 の例外を増やさない）
  - **D3-2: 置く時だけ 4px の隙間を見る。きっかけには入れない** — ボタンの大きさの見積もりが実物より最大 3.5px 小さく、隙間 0 では隣に置いたボタンが実物で 1.5px 重なった（P0 の 4）。
    P0 の再測（判定 0 / 置き 4px）で、動いた線の数は隙間 0 と同じ、4px 以内に残る組は回した線のボタンとの組と解けない 1 組だけ（P0 結果の「D3-2 の再測」）
- **D4: 案 A** — `placeButton` は今のまま（避けるボタンが動かした後の taken になるだけ）。置けない時の中点はスコープ外
- **D5: 案 A** — `routeEdges` が返す。形は試作どおり `EdgeRoute` に折れ線の空の形（`points: []`）でボタンの位置だけを返す形を基に P1 で確定する。
  線の部品は、返された絶対座標をそのまま使い、`adjustEdgeLabelPosition` を重ねて掛けない
- **D6: 受け入れ条件 4 の 33ms の絶対の基準をやめ、「今のコードと比べた、ドラッグ中の 1 回の中央値の増分が 3ms 以下」にする** — P0 のブラウザの増分は中央値 0.3〜0.6ms。
  枠の無い大きな図の n57 は今のコードでも中央値 37〜43ms で、この spec が足した分ではない（spec 19 の候補「大きな図のドラッグを軽くする」で扱う）

## 現況（2026-10-09、コードを読んで確かめた。画面の測りは P0）

- **回さない線のボタン**は線の部品（`features/flowchart/components/edge/editable-edge.tsx`）が置く: 曲線の中点（`getBezierPath` のラベルの位置、t = 0.5）に
  `adjustEdgeLabelPosition`（`features/flowchart/hooks/edge-layout.ts`）のずれを足した所。ずれが付くのは**互いに逆向きの組**（`A → B` と `B → A`）と自己ループだけで、
  逆向きの組は ±20px を組の中の順で振り、自己ループはノードの周りの円に振る（`calculateEdgeOffset`）。それ以外の線は中点そのまま
- **回した線のボタン**は `routeEdges`（`features/flowchart/utils/edge-route.ts`）の `placeButton` が置く: 避けるもの・先に置いた回した線のボタン・**回さない線のボタン（今の位置）**と重ならない所（spec 19 D3 の案 A'）。
  回さない線のボタンは動かさない。したがって**重なりが残るのは回さない線どうし**（と、下の `placeButton` の置けない時）
- **`placeButton` は、どこにも置けない時に、重なりを見ずに一番長い線分の中点へ置く**（spec 17 D3 のまま、`placeButton` の最後）。回した線のボタンが回さない線のボタンと重なるのはこの時だけ
- **自己ループは `routeEdges` の外**（`routeEdges` の初めで飛ばし、`taken` にも入れない）。ノードの自己ループは曲線の中点 + `adjustEdgeLabelPosition` の円のずれ、
  枠の自己ループは `frameSelfLoopPath`（`utils/frame-edit.ts`）の折れ線とラベルの位置で、線の部品が描く。どちらも位置は `routeEdges` の入力（矩形と接続点）から求められる
- ボタンの大きさの見積もりは `estimateButtonSize`（`hooks/use-edge-routes.ts`）: ラベルが空で 101×28、全角 12px・半角 7px で横に伸びる（折り返さない）。
  ボタンはラベルの箱・矢印の種類の切り替え・削除（×）を横に並べたもの
- 接続点はノードごとに出口 1 つ・入口 1 つ（`handleBounds[...][0]`）。**同じノードから出る線は同じ点から出る**
- 取り込みの段組み（枠の無い図、`flow-editor.tsx` の `layoutNodes`）: ノード 240×48、TD・BT は段の送り 150・同じ段の送り 250、LR・RL は段の送り 450・同じ段の送り 150。
  見込み（**定数から計算しただけで、画面では測っていない**）: TD で 1 つのノードから同じ段の隣り合う 2 つへ出る線は、中点が横に 125px しか離れず、ラベルが全角 3 字を超える（幅 124 超）と重なる。
  LR では中点が縦に 75px 離れ、高さ 28 のボタンは重ならない。TD の段の隙間は 102px で、高さ 28 のボタンを縦に滑らせられるのは中点から ±37px ほど
- **同じ向きの平行な線**（`A --> B` を 2 回）は取り込みで別の ID になって残る（`from-mermaid.ts` の `uniqueId`）。曲線もボタンも完全に重なる。
  互いに逆向きの組に平行な線が混じる時、`adjustEdgeLabelPosition` は線を出口と入口で探す（`allEdges.find`）ので、**平行な 2 本は同じずれを受けて重なったまま**
- `routeEdges` は回した線の `EdgeRoute`（折れ線とボタンの位置）だけを返し、線の部品は `useEdgeRoute(id)` で受ける。回さない線の位置を返す口は無い。
  線の部品は、回した線のボタンには `adjustEdgeLabelPosition` を掛けない（`routed ? labelX : adjusted.adjustedX`）
- 速さ（spec 19 P1、窓が隠れた環境）: ノード 110・線 150 の図で、全部の計算は枠あり 58〜59ms・枠なし 61〜78ms、ドラッグ中の 1 回の中央値は枠あり 14〜25ms・枠なし 12〜36ms
  （spec 19 の基準 33ms の際。枠の無い図の線の多いノード n57 は 4 回中 1 回 36ms、中央値の中央値は 30ms）

## 言葉の定義

```text
ボタン(線)          = 線のラベルのボタンの矩形（estimateButtonSize の大きさ）
今の位置(線)        = 回さない線: 曲線の中点 + adjustEdgeLabelPosition のずれ（線の部品が今置く所。routeEdges の curveLabel）
                      自己ループ: 線の部品が今置く所（ノードは curveLabel、枠は frameSelfLoopPath のラベルの位置）
重なる(b1, b2)      = 2 つのボタンの矩形の内側が交わる（縁が接するだけは重ならない。隙間を足すかは D3）
曲線の点(線, s)     = 今の曲線（bezierPolyline の 48 刻みの折れ線）の上で、中点から道のり s だけ進んだ点。s < 0 は出口の側、s > 0 は入口の側
候補(線)            = D1 で決める有限の点の並び。並びの順に試す
置ける(線, c)       = c を中心にボタンを置いた時、置き場の障害（D3）のどれとも重ならず（ボタンとは 4px の隙間を空ける。D3-2）、かつ今の曲線がボタンの縁から 2px（BUTTON_LINE_INSET）以上内側を通る
ずらす線            = 置き方の手順（D2）で、今の位置から動かす回さない線
```

## 決めること

### D1. ずらし方と候補（**裁定 = 案 A**）

- **案 A（推奨）: 自分の曲線の上で滑らせる** — ずらす線のボタンを、次の候補の順に試し、最初に置ける所に置く（spec 19 裁定 2 の案 D、`placeButton` の考え方を曲線に使う）
  1. **曲線の上**: 曲線の点(線, s) で、s = −8, +8, −16, +16, … と `ROUTE.BUTTON_GAP`（8px）刻みに、道のりで中点に近い順。同じ近さでは出口の側を先（`placeButton` の `sign` の順と同じ）。
     s は曲線の両端まで（端のノードに重なる候補は D3 で落ちる）
  2. **曲線と直交する向き**: 1 で置けない時、1 の各点で、ボタンを 2px（`BUTTON_SHIFT_STEP`）刻みに −d, +d の順でずらして 1 と同じ順に試す。
     向きは、その点の曲線の向きが横寄り（|dx| ≥ |dy|）なら縦、縦寄りなら横。d は線がボタンの縁から 2px 以上内側を通る範囲まで（spec 19 P1 の 2 段目と同じ考え）
  3. **置けなければ今の位置のまま**（重なりを残す）。動かした線として数えない
- 案 B: 曲線から離して置き、細い引き出し線で曲線とつなぐ — 置ける所は広いが、Web 版の見た目に新しい部品が増える
- 案 C: 重なる組の片方を spec 17 の回り道で回す — ボタンのために線の形まで変わり、角張った線が増える。回す線が増えるのでドラッグが重くなる（spec 19 D4 が際）
- 案 D: 重なりは残し、マウスを乗せたボタンを一番上に出す — 押せるが、重なったままでは読めない。比べるための案

推す理由: ボタンが自分の線の上にあれば、どの線のボタンかが見て分かる（ずらした後もボタンの中を自分の線が通る）。線の形は変わらない。
**短い線は置ける候補が無いことがある**（中点から少し動くと端のノードにかかる）。その時は 3 で今の位置に残る — 解けない組として P0 で数え、線の長さとボタンの大きさの比で分ける。
候補は有限なので、候補と候補の間にしか置ける所が無い時も解けない（受け入れ条件 1 は「候補に置ける所がある限り」と書く）。

### D2. 置き方の手順（**裁定 = 逐次に置く**）

組ごとの規則（rev0 の「重なる組の後ろの線を動かす、動かした先が重なればその線も」）は、3 本以上が関わる時にどれを動かすかが決まらない（査読 1-2・2-②・3-5）。手順で決める:

```text
0. 回した線の折れ線を決める（今の routeEdges の探索と separate。変えない）
1. taken = 全部の回さない線の今の位置 + 全部の自己ループの今の位置
2. 回さない線を線の並び（edges の順 = 定義の順）に 1 本ずつ見る。線 e について
     先(e) = taken のうち、e より前の回さない線の確定した位置と、全部の自己ループ
     e の今の位置が 先(e) のどれかと重ならなければ → e は動かさない（確定）
     重なれば → e はずらす線。D1 の候補を、置き場の障害（D3）で試す。
                置き場の障害のボタンは taken から e 自身を除いた全部（e より後ろの線は今の位置のまま入っている）
                置ければ taken の e をその位置に替える。置けなければ今の位置のまま
3. 回した線のボタンを、今の placeButton で置く（避けるボタン = 2 の後の taken。spec 19 D3 の案 A' と同じ形で、中身が動かした後の位置になる）
```

- **動かすのは「前の線の確定した位置」と重なる線だけ**。前の線は、自分の今の位置のままか、後ろの線の今の位置を避けた所へ動いているので、
  **今の位置で何とも重ならない線は動かない**（受け入れ条件 3）。重なっていても、相手が前で動いて退いた時は動かない
- ずらした先は、後ろの線の今の位置も避けるので、**動かしたことで新しい重なりは生まれない**（連鎖は起きない）
- 自己ループは動かさず、全部の回さない線が避ける（先(e) に入る）。自己ループと重なる回さない線は、並びに関わらず回さない線の方が動く
- 案 B: 全部の回さない線を並びの順に置き直す（先に置いたものだけを避ける）— 重なっていない線も動きうる
- 案 C: 短い線（候補の少ない線）を先に確定させ、長い線を動かす — 解ける組は増える見込みだが、どの線が動くかが人に読みにくい

推す理由: 重なりの無い線の位置は今と同じ。並びが定義の順で決まるので、**ドラッグ中に関わりの無い線のボタンが入れ替わってちらつかない**見込み
（見込み。P0 で、ドラッグ中に動いたボタンの数を見る）。

### D3. 動かすきっかけと置き場の障害（**裁定 = 案 A、D3-1 = 入れない、D3-2 = 置く時だけ 4px**）

「何と重なったら動かすか（きっかけ）」と「動かした先が何を避けるか（置き場の障害）」を分ける（rev0 は 1 つの節に混ぜていた, 査読 1-5）。

- **きっかけ**: D2 の 2 のとおり、**ほかのボタンとの重なりだけ**。ノード・枠の見出しとの重なりではきっかけにしない（今の位置がノードに少しかかるだけの線は動かさない）
- **置き場の障害（案 A、推奨）**: ① taken から自分を除いた全部のボタン ② **全部のノード（端を含む）** ③ 全部の枠の見出しの帯。枠の本体は障害にしない（枠の中の線のボタンは枠の中にある）
- 案 B: 置き場の障害をボタンだけにする — ノードの上へ滑らせて、ボタンがノードを隠しうる

「端を含む」の理由: 曲線の端の近くはノードの縁なので、端を障害にしないと、滑らせたボタンが出口・入口のノードに乗る。
今の位置がノードや見出しにかかっていても、それはきっかけでないので動かさない。**動かした先だけ**が障害を避ける。
回さない曲線が枠の見出しを通る線（候補 ⑦ の前半）は、見出しの上に候補が無くても、ほかの候補か今の位置に残る（D1 の 3）。

**回した線の折れ線は置き場の障害にしない**（ボタンが別の線の上に乗るのはスコープ外。回さない線どうしの曲線も同じ）。

P0 の数で決めること（裁定済み。冒頭の「裁定」）:

- **D3-1 ノードに少しかかるボタン**: 今の位置がノードにかかる深さ 12px 未満の回さない線（spec 19 裁定 2 で回さない線）も、きっかけに入れるか。
  入れるなら、D2 の 2 の「動かさない」の条件と受け入れ条件 3 に同じ例外を付ける（査読 3-4）。P0 で本数と、入れた時に動く線の数を数える
- **D3-2 隙間**: 重なりの判定に隙間を足すか（縁が 2px 離れていても、ボタンの枠線が接して 1 つに見える）。P0 の 4 の画面で見る

### D4. 回した線のボタンが置けない時（**裁定 = 案 A**）

D2 の 3 で、回した線のボタンは今の `placeButton` で置く。`placeButton` はどこにも置けない時に重なりを見ずに一番長い線分の中点へ置く（現況）ので、
**動かした回さない線のボタンと重なりうる**（査読 2-①・3-2）。

- **案 A（推奨）: 今のまま（置けない時は線分の中点）。受け入れ条件 1 は「回した線のボタンは、置ける所がある限り」と書く** — spec 17・19 で決めた置き方を変えない。
  P0 で、`placeButton` が置けなかった線の本数を数える（spec 19 P1 の図では 0 の見込み。測っていない）
- 案 B: 回した線のボタンが置けない時、その線のボタンと重なる回さない線のボタンを D1 の候補で動かし直す — 手順が巻き戻しを持ち、D2 の「連鎖は起きない」が崩れる

### D5. 計算の置き場所と返す形（**裁定 = 案 A**）

- **案 A（推奨）: `routeEdges` が回さない線のボタンの位置も求めて返す**（ずらした線だけ）。返す形は P1 で決める（`EdgeRoute` に折れ線の無い形を足すか、別の `Map` か）。
  - **返す位置は絶対座標で、`adjustEdgeLabelPosition` のずれを足した後の位置**。線の部品は、返された位置にずれを足さない（回した線と同じ分岐。査読 2 の付記）
  - 返されなかった回さない線は、線の部品が今の位置（中点 + `adjustEdgeLabelPosition`）に置く（今のまま）
  - 自己ループの今の位置（D2 の 1）は、`routeEdges` が入力から求める（ノードは `curveLabel`、枠は `frameSelfLoopPath`）。描くのは今のまま線の部品
- 案 B: 線の部品がそれぞれ求める — ほかの線のボタンの位置が要るので、線ごとに全部を見ることになる（線の数の 2 乗）

`adjustEdgeLabelPosition`（互いに逆向きの組の ±20px）は**今の位置の定義として残す**（重ならない組の見た目を変えない）。
平行な線が同じずれを受ける件は、D2 の手順で後ろの線が滑って解ける見込みなので、`adjustEdgeLabelPosition` 自体は直さない — P0 でそう解けるかを確かめる。

### D6. 速さ（**裁定 = 増分の基準**）

- ずらす計算は経路の探索より軽い見込み（候補の点 × 近くの矩形）。ただし**ドラッグ中は、動いたノードと関わりの無い線のボタンも、ほかのボタンの位置で動きうる**ので、毎回全部の回さない線を見る
- **基準**（rev2 で改めた。spec 19 D4 と同じ図・同じ測り方）: ノード 110・線 150 の図（枠あり・枠なし）で、全部の計算 1 回が 100ms 以下、
  **ドラッグ中の 1 回の中央値の、今のコードからの増分が 3ms 以下**（rev1 は中央値 33ms 以下。今のコードでも超える図があり、この spec では満たせない）
- spec 19 で枠の無い図のドラッグの中央値が際（12〜36ms）なので、**足す時間を P0 で別に測る**（同じ環境で今のコードと並べる）。P0 の後の判断（数は仮。P0 の後に利用者と決める）:
  - 足す時間（ドラッグ中の 1 回の中央値の増分）が **3ms 以下** → そのまま P1

- **D5: 案 A**（`routeEdges` が返す）。試作では `EdgeRoute` に折れ線の空の形（`points: []`）でボタンの位置だけを返し、線の部品は折れ線が空なら曲線のまま返された位置に置いた。P1 で返す形を決める
- **D6: 今の形のまま P1 へ**（ずらしの増分はドラッグ中の中央値で 0.3〜0.6ms）。**受け入れ条件 4 は「今のコードと比べて、ドラッグ中の 1 回の中央値の増分が 3ms 以下」に改める**ことを推す。
  33ms の絶対の基準は、枠の無い大きな図の n57 が今のコードでも超えていて、この spec では満たせない（spec 19 の候補で扱う）

## 査読の採否（rev0 → rev1）
