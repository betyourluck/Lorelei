# Spec: ER 図の名前を、Mermaid で書ける形にして書き出す（空白・書きかけの列）

**ID**: 13
**Date**: 2026-09-29
**Status**: 起票（rev0。裁定 3 件済み。査読前）
**Branch**: なし（Phase 単位で main へ直接コミット）

## Goal

ER 図のエディタでテーブル名・列を編集した結果が、**いつも Mermaid として正しく、同じ図として読み戻せる**コードになるようにする。
spec 11 で「ER 図の名前の空白（生成器が誤ったコードを書く）」を既知の制約として LORELEI.md に書いたが、リサーチで**制約では済まない**と分かった（下の現況）:
生成器の出力はデスクトップの自動保存の `source` そのもので、保存した図は開き直す時に Rust の変換にかけ直すため、**空白の名前を付けた図は一覧から開けなくなるか、黙ってテーブルが割れる**。

**フォーク元の改善**（Web 版のコード生成も同じ誤りを出す）なので、デスクトップの変更とはコミットを分け、上流へ PR で返せる形にする（掟）。

## 裁定（2026-09-29、利用者）

- **D1**: テーブル名は要る時だけ `"…"` で囲む（いつも囲む案は採らない）
- **D2**: Mermaid に書けない列は書き出さずに知らせる（置き換える案・確定時に弾く案は採らない。デスクトップで開き直すとその列が消えることを受け入れる）
- **D3**: テーブル名は確定で反映し、空・空白だけの確定は前の名前に戻す（打鍵ごとの反映のまま ID で補う案は採らない）

## 現況（2026-09-29、使い捨てのテストで実測。mermaid.js 11.17.2 = TS の取り込み / merman = Rust の `to_editor`）

### 生成器の出力がそのまま保存され、開き直す時に読み直される

- `lib/desktop/doc-session.ts:125` の `toSource` が `generateERDiagramMermaidCode` の出力を `Document.source` にし、自動保存（`AUTOSAVE_DELAY_MS = 1000`）で書く。
  Rust の `save_document` は中身を検査しない（`src-tauri/src/lib.rs:225`）
- 一覧から開く時は `loadDocument` → `convertSource`（Rust の `request_from_source` → `to_editor`）で読み直す（`lib/desktop/use-doc-session.ts:220〜228`）。AI の `read_diagram` もこの `source` を返す
- テーブル名の入力欄は**打鍵ごとに**名前を反映する（`er-table-content.tsx:189`）。「カラム追加」は名前も型も空の列を足す（同 59 行）。どちらも入力を検査しない

### 実測

| エディタの状態 | 生成器の出力 | mermaid.js | merman |
|---|---|---|---|
| テーブル名 `注文 明細`（関係あり） | `注文 明細 {` … `顧客 \|\|--o{ 注文 明細 : 行う` | **誤り**（関係の行） | **誤り** → **一覧から開けない** |

| 列名に `:`・`/`・`"`、数字始まり（`1a`）、`PK` | そのまま | 誤り | （未測。P0） |
| 列名に `-`・`.`・`(` `)`、全角数字始まり（`２番`）、型に `,`・`[]`・日本語 | そのまま | 通る | `a(b)`・`decimal(10,2)`・`整数` は通る |

- **引用符で囲んだテーブル名**（`"注文 明細" {`・`顧客 ||--o{ "注文 明細" : r`）は両方で通り、名前は囲みの中身（`注文 明細`）になる。`"1abc"`・`"end"`・`"direction"`・`"a(b)"` も
  mermaid.js で通る（merman は `"end"`・`"a(b)"` を確認。`"direction"` は P0）。空の `""` は両方で誤り
- 囲んだ中の `"` は `#quot;` で書けるが、**取り込みで元の文字に戻らない**: TS の写し（`components/ui/mermaid-render.ts`）は ER 図の `alias` は `decodeText` で戻すが**テーブルの名前は戻さない**。
  Rust の `to_editor` は戻す処理を持たない（名前が `a ﬂ°quot¶ßb` になる）
- 別名（`e1["注文 明細"]`）でも空白を書けるが、取り込みは識別子（`e1`）を名前にし別名を落とす（spec 11 の対応表）ので、往復で名前が変わる — 使わない
- **初期図の突き合わせ**: data_contract の `initial_sources` は、エディタの初期図を生成器にかけた出力を**一字一句**で持ち、vitest で生成器と突き合わせる（spec 04 D4-2）。
  初期図の名前（`ユーザー`・`テーブルN`・`id`・`varchar(255)` 等）の出力が変わると、この基準を張り替えることになる

## 決めること

### D1. テーブル名は、そのままでは読めない時だけ `"…"` で囲む（**裁定 1**）

- 囲まない条件（両方の解析器で 1 つの名前として読める、と P0 で確かめた形だけ）: 文字か `_` で始まり、文字・数字・`_`・`-` だけで、予約語（`end`・`direction`・`style`・`class`・`classDef`・`subgraph`・
  `erDiagram`・`accTitle`・`accDescr` など。P0 で両方の文法から拾う）でない。ほかは囲む。関係の行の名前も同じ形で書く
- 囲んだ中の `"` は `#quot;`、`#語;` の `#` は `#35;`（spec 11 D5 の関係のラベルと同じ規則）
- 取り込みは両方でテーブルの名前を元の文字に戻す（TS は写しで `decodeText` をテーブルの名前にも当てる。Rust は `to_editor` の ER 図の名前に同じ戻しを足す）
- **対案（裁定で採らなかった）**: いつも囲む。規則は単純になるが、すべての図のコードが変わり、`initial_sources` の基準と、保存済みの図の `source` の見た目が変わる

### D2. 書けない列は、書き出さずに知らせる（**裁定 2**）

Mermaid は列名・型に空白を書く方法を持たない（囲んでも誤り）。列は「型 名前」の 2 語が揃わないと誤りになる。

- **生成器**: 名前か型が空の列（書きかけ）と、名前・型が書けない形の列は**コードに書かない**（図全体を誤りにしない）。書けない形は P0 で両方の文法から決める
  （空白・`:`・`/`・`"`、名前の数字始まり、`PK`・`FK`・`UK` 等の予約語が候補）
- **入力欄**: 書けない値のセルに赤枠と理由（「列名に空白は使えません（Mermaid に書けません）」）を出す。値は消さない（直すのは人）
- **コード生成のダイアログ**: 書き出さなかった列があれば「書き出していない列: 注文.注文 日（空白）、注文.（名前が空）」と出す
- デスクトップ: 書き出さなかった列は保存する `source` にも入らないので、**その図を一覧から開き直すと消える**。エディタを開いている間は残る。裁定 2 でこれを受け入れた
- **対案（裁定で採らなかった）**: (B) 生成器が書ける形に置き換える（空白 → `_`）。図は必ず開けるが、名前が黙って変わる / (C) 入力欄で確定時に弾いて前の値に戻す（書きかけの列は B と同じ扱いが別に要る）

### D3. 空のテーブル名は確定させない（**裁定 3**）

- テーブル名の入力欄を列の入力欄（`CellEditor`）と同じく**確定（Enter・フォーカスが外れる）で反映**にし、空・空白だけで確定したら前の名前に戻す。
  打鍵の途中の空の名前が自動保存に乗らない
- **対案（裁定で採らなかった）**: 打鍵ごとの反映は残し、生成器が空の名前をノードの ID（`テーブル3` 等）で書く。操作は変わらないが、開き直すと名前が変わる

### D4. 既知の制約の書き換え

- LORELEI.md の「ER 図のテーブル名・列名に空白があると…」を、この spec の結果に合わせて書き換える（テーブル名は書ける・列名と型の空白は書けないので書き出さない）
- data_contract の `generator` に ER 図の名前の規則を足す

- **P3**（Rust）: `to_editor` の ER 図の名前の戻し。`crates/lorelei_core/tests/editor.rs` に同じ入力（Red → Green）

  Web 版（静的書き出し。`TAURI_ENV_PLATFORM` 付きで `out/`、failures #18）のコード生成でも

## 受け入れ条件

1. テーブル名に空白・記号・予約語・数字始まり・`"` があっても、生成器のコードが mermaid.js と merman の両方で通り、取り込むと同じ名前に戻る
2. 書きかけの列・書けない列があっても、生成器のコードは通る。書き出さない列は、入力欄の印とコード生成のダイアログで分かる
3. 空のテーブル名は確定しない（自動保存に空の名前が乗らない）
4. デスクトップで、名前を編集した図を閉じて一覧から開き直すと、同じテーブル・関係に戻る（D2 の書き出さない列を除く）
5. 初期図の生成器の出力が変わらない（`initial_sources` の突き合わせが緑のまま）
6. vitest は全件緑かつ exit 0、`cargo test --workspace` 通過

## スコープ外

- 同じ名前のテーブルが 2 つある時（コードでは 1 つに合わさる）
- 既に誤ったコードで保存された図の救済（開けない図は、AI の `update_diagram` で書き直せる）
- フローチャートの変数名（`getSafeVariableName` が既に書ける形にしている）
- 列の注釈（`"主キー"`）をエディタで扱うこと
