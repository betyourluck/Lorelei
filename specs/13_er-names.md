# Spec: ER 図の名前を、Mermaid で書ける形にして書き出す（空白・書きかけの列）

**ID**: 13
**Date**: 2026-09-29
**Status**: rev2（裁定 3 件済み・査読 2 本を反映・**P0・P1 着地**。P2 待ち。merman の不具合は spec 14 で扱う）
**Branch**: 切らない（Phase 単位で main へ直接コミット）。ただし**フォーク元の改善（P1・P2）とデスクトップ・Rust（P3・P4）はコミットを分け**、フォーク元のコミットだけで上流へ PR を出せる形にする

## Goal

ER 図のエディタでテーブル名・列を編集した結果が、**いつも Mermaid として正しい**コードになり、**テーブル（名前）と関係はいつも同じ図として読み戻せる**ようにする。
列は、Mermaid に書けない形（書きかけ・列名や型に空白 など）の時だけ書き出さず、そのことを知らせる（裁定 2。デスクトップで開き直すとその列は消える）。

spec 11 で「ER 図の名前の空白（生成器が誤ったコードを書く）」を既知の制約として LORELEI.md に書いたが、リサーチで**制約では済まない**と分かった（下の現況）:
生成器の出力はデスクトップの自動保存の `source` そのもので、保存した図は開き直す時に Rust の変換にかけ直すため、**空白を含む名前を付けた図は一覧から開けなくなるか、黙ってテーブルが割れる**。

**フォーク元の改善**（Web 版のコード生成も同じ誤りを出す）なので、上流へ返せる形にする（掟。Branch の行）。

## 裁定（2026-09-29、利用者）

- **D1**: テーブル名は要る時だけ `"…"` で囲む（いつも囲む案は採らない）
- **D2**: Mermaid に書けない列は書き出さずに知らせる（置き換える案・確定時に弾く案は採らない。デスクトップで開き直すとその列が消えることを受け入れる）
- **D3**: テーブル名は確定で反映し、空・空白だけの確定は前の名前に戻す（打鍵ごとの反映のまま ID で補う案は採らない）

## 現況（2026-09-29、使い捨てのテストで実測。mermaid.js 11.17.2 = TS の取り込み / merman = Rust の `to_editor`）

### 生成器の出力がそのまま保存され、開き直す時に読み直される

- `lib/desktop/doc-session.ts:125` の `toSource` が `generateERDiagramMermaidCode` の出力を `Document.source` にし、自動保存（`AUTOSAVE_DELAY_MS = 1000`）で書く。
  Rust の `save_document` は中身を検査しない（`src-tauri/src/lib.rs:225`）
- 一覧から開く時は `loadDocument` → `convertSource`（Rust の `request_from_source` → `to_editor`）で読み直す（`lib/desktop/use-doc-session.ts:220〜228`）。AI の `read_diagram` もこの `source` を返す
- テーブル名の入力欄は**打鍵ごとに**名前を反映する（`er-table-content.tsx:189`）。列の入力欄（`CellEditor`）は Enter・フォーカスが外れた時に反映し、Esc の扱いは無い。
  「カラム追加」は名前も型も空の列を足す（同 59 行）。新しいテーブルの名前は `テーブル{ID}`（`er-diagram-helpers.ts:26`）。どれも入力を検査しない

- 列の行は、**0 語は飛ばす・1 語は誤り・2 語（型 名前）で成立**（3 語目以降はキーと注釈）
- **引用符で囲んだテーブル名**（`"注文 明細" {`・`顧客 ||--o{ "注文 明細" : r`）は両方で通り、名前は囲みの中身（`注文 明細`）になる。`"1abc"`・`"end"`・`"direction"`・`"a(b)"` も
  両方で 1 つの名前として通る（merman の `"1abc"` は P0）。空の `""` は両方で誤り
- 囲んだ中の `"` は `#quot;` で書けるが、**ER 図のテーブルの名前は取り込みで元の文字に戻らない**: TS の写し（`components/ui/mermaid-render.ts`）は ER 図の `alias` は `decodeText` で戻すが名前は戻さない。
  Rust の `to_editor` も戻さない（名前が `a ﬂ°quot¶ßb` になる）
- **フローチャートのラベルは Rust でも戻る**（merman が解析の段階で戻す。`A["say #quot;hi#quot;"]` → `say "hi"`、`#35;1;` → `#1;`）。戻らないのは ER 図のテーブルの名前だけ
- 別名（`e1["注文 明細"]`）でも空白を書けるが、取り込みは識別子（`e1`）を名前にし別名を落とす（spec 11 の対応表）ので、往復で名前が変わる — 使わない
- **初期図の突き合わせ**: data_contract の `initial_sources.erDiagram` は `erDiagram\n  ユーザー {\n    int id PK\n    varchar(255) name UK\n  }`（一字一句。vitest で生成器と突き合わせる, spec 04 D4-2）。
  D1・D2 の規則は、この名前（`ユーザー`・`id`・`name`・`int`・`varchar(255)`）と新しいテーブルの `テーブル{ID}` を**囲まない・書き出す**側に入れる

## 決めること

### D1. テーブル名は、そのままでは読めない時だけ `"…"` で囲む（**裁定 1**）

（rev2: P0 の実測で確定。根拠は「P0 結果」）

- **囲まない条件**（3 つすべて）: ① 正規表現 `^[\p{L}_][\p{L}\p{N}_-]*$` に合う（`\p{L}` は Unicode の文字 = ひらがな・カタカナ・漢字・長音 `ー`・`é` を含む。数字始まりは全角も含めて囲む）
  ② 大文字小文字を問わず `erdiagram`・`style`・`classdef`・`class`・`subgraph`・`end`・`direction`・`acctitle`・`accdescr`・`many`・`one`・`to` で**始まらない**（境界を見ない前方一致。
  `tokens`・`endpoint`・`classes` も囲む — merman は `to`・`one`・`many` を境界なしで取り、mermaid.js は `end注文` のような ASCII の語の後の非 ASCII を境界とみなすため）
  ③ `u-`・`u.` で始まらない。**それ以外は囲む**
- **関係のラベルも同じ関数で書く**（rev2 で範囲に足した。spec 11 D5 の規則は、文字・数字・`_`・`-` だけのラベルを囲まず、`to`・`one`・`end`・`1x` などのラベルで誤りになる — P0 結果）。
  今のラベルの既定 `relation` と初期図（関係なし）の出力は変わらない
- **囲む時の書き換え**（この順）: ① `#` のうち `#語;` の形の先頭（`#(?=[\p{L}\p{N}_]+;)`）だけを `#35;`（`#` 単体はそのまま）→ ①' `&` → `#38;`（P1 で足した）→ ② `"` → `#quot;` → ③ `%` → `#37;` → ④ `\` → `#92;`
  → ⑤ 大文字小文字を問わず `direction` + 空白（JS の `\s`）+ `tb`・`bt`・`rl`・`lr` の並びの**空白の 1 字ずつ**を `#<その字の符号位置>;`（ASCII の空白なら `#32;`、全角の空白なら `#12288;`）。
  ①を先にするので①'〜⑤で入れた `#…;` の `#` は書き換わらない。①'は、名前の中の `&amp;` のような文字が取り込みで実体参照として解かれて `&` に化けないため（TS の写しの `decodeText` は `&…;` を解く）。
  ③④は mermaid.js と merman の両方が囲んだ名前に `%`・`\` を許さないため、⑤は mermaid.js の `.*direction\s+(TB|BT|RL|LR)` が
  囲みの中でも行ごと向きの行として食うため（名前は誤り、関係のラベルは**関係ごと黙って消える**）
- 取り込みは両方でテーブルの名前と関係のラベルを元の文字に戻す（TS は写しで `decodeText` をテーブルの名前にも当てる = P1。関係のラベルは既に戻る。
  Rust は `to_editor` の ER 図の名前と関係のラベルに merman の `merman::entities::decode_mermaid_entities_to_unicode` を当てる = P3）
- **対案（裁定で採らなかった）**: いつも囲む。規則は単純になるが、すべての図のコードが変わり、`initial_sources` の基準と、保存済みの図の `source` の見た目が変わる

### D2. 書けない列は、書き出さずに知らせる（**裁定 2**）

Mermaid は列名・型に空白を書く方法を持たない（囲んでも誤り）。列の行は 0 語なら飛ばされ、1 語なら誤り、2 語（型 名前）で成立する。

- **生成器**: 名前か型が空（空白だけを含む）の列と、名前・型が書けない形の列は**コードに書かない**（図全体を誤りにしない）。全部の列を書かなかったテーブルは `名前 {` / `}`（今の列 0 件の形）で書く — 両方で `columns: []` に戻る（実測）
- **書ける形**（rev2: P0 で確定。両方の共通部分 = mermaid.js の列の規則 25 と同じ）: 列名・型とも、1 字目が `A-Za-z`・`_`・`*`・U+00C0 以上、2 字目以降が `A-Za-z0-9`・`_`・`-`・`*`・`.`・`,`・`(` `)`・`[` `]`・U+00C0 以上
  （UTF-16 の符号単位で見る。絵文字など U+10000 以上も通る）で、大文字小文字を問わず `pk`・`fk`・`uk` の後が語の文字（`A-Za-z0-9_`）でない形で**始まらない**（`pk`・`PK-x` は書けない、`pk_id` は書ける）。
  型だけは、加えて `~` を 2 つ含む総称型（`List~int~`）も書ける。それ以外（空白・`:`・`/`・`'`・`"`・`#`・`%`・`~` 1 つ・数字始まり・`-` `.` `(` 始まり・U+0080〜U+00BF の `°` `·` `¥` など）は書けない
- **入力欄の印**（確定した値で判定する）:
  - 名前も型も空の列（「カラム追加」の直後）: 枠は出さない（足した直後に赤が 2 つ点くのを避ける）。コード生成のダイアログの一覧には出す
  - 片方だけ空の列: 空の側のセルに赤枠と「型が空です（この列はコードに書き出しません）」
  - 書けない形の値: そのセルに赤枠と理由（「列名に空白は使えません（Mermaid に書けません）」）。値は消さない（直すのは人）
- **コード生成のダイアログ**: 書き出さなかった列があれば「書き出していない列: 注文.注文 日（空白）、注文.（名前と型が空）」と出す
- デスクトップ: 書き出さなかった列は保存する `source` にも入らないので、**その図を一覧から開き直すと消える**。エディタを開いている間は残る。裁定 2 でこれを受け入れた
- **対案（裁定で採らなかった）**: (B) 生成器が書ける形に置き換える（空白 → `_`）。図は必ず開けるが、名前が黙って変わる / (C) 入力欄で確定時に弾いて前の値に戻す（書きかけの列は B と同じ扱いが別に要る）

### D3. 空のテーブル名は確定させない（**裁定 3**）

- テーブル名の入力欄を列の入力欄（`CellEditor`）と同じく**確定（Enter・フォーカスが外れる）で反映**にする。空・空白だけで確定したら、**確定前の名前**（新しいテーブルなら `テーブル{ID}`）に
  **黙って戻す**（戻った名前が見えることを知らせとする。赤枠・通知は出さない）。Esc の扱いは `CellEditor` と同じく持たない（フォーカスが外れた時に確定する）
- 打鍵の途中の空の名前が自動保存に乗らない。空白を**含む**名前（`注文 明細`）は確定してよい（D1 で囲んで書く）
- **対案（裁定で採らなかった）**: 打鍵ごとの反映は残し、生成器が空の名前をノードの ID（`テーブル3` 等）で書く。操作は変わらないが、開き直すと名前が変わる

### D4. 既知の制約の書き換え

- LORELEI.md の「ER 図のテーブル名・列名に空白があると…」を、この spec の結果に合わせて書き換える（テーブル名は書ける・列名と型の空白は書けないので書き出さない）
- data_contract の `generator` に ER 図の名前と列の規則を足す

## 受け入れ条件

1. テーブル名と関係のラベルに空白・記号・予約語・数字始まり・`"`・`%`・`\`・`direction LR` があっても、生成器のコードが mermaid.js と merman の両方で通り、取り込むと同じ名前・ラベルに戻る
   （TS は P1、Rust は P3 で判定。両方そろって通過）
2. 書きかけの列・書けない列があっても、生成器のコードは通る。書き出さない列は、入力欄の印（D2 の出し分け）とコード生成のダイアログで分かる
3. 空・空白だけのテーブル名は確定しない（自動保存に空の名前が乗らない）
4. デスクトップで、名前を編集した図を閉じて一覧から開き直すと、同じテーブル・関係に戻る（D2 の書き出さない列を除く）
5. 初期図の生成器の出力が変わらない（`initial_sources` の突き合わせが緑のまま）
6. vitest は全件緑かつ exit 0、`cargo test --workspace` 通過

## スコープ外

- 同じ名前のテーブルが 2 つある時（コードでは 1 つに合わさる）
- 既に誤ったコードで保存された図の救済（開けない図は、AI の `update_diagram` で書き直せる）
- フローチャートの変数名（`getSafeVariableName` が既に書ける形にしている）・ラベル（Rust でも戻る。現況）
- 列の注釈（`"主キー"`）をエディタで扱うこと
